## One Route, Every Consumer

<Tabs>
<Tab title="Routes">

```ts twoslash
// ---cut-start---
// @filename: router.ts
import { respond, route } from "@rest-rpc/server";
import * as z from "zod";

declare function createPost(
	title: string,
	body: string,
): { id: string; title: string; body: string };
declare function findPost(
	id: string,
): { id: string; title: string; body: string } | undefined;
// ---cut-end---
// POST /posts/create, JSON body, 200 result.
const create = route
	.body(z.object({ title: z.string(), body: z.string() }))
	.handler(({ body: { title, body } }) => createPost(title, body));

// GET /posts/:id with params, query, headers, an error, and response headers.
const get = route
	.get("/posts/:id")
	.params(z.object({ id: z.string() }))
	.query(z.object({ preview: z.enum(["true", "false"]).optional() }))
	.headers(z.object({ "x-request-id": z.string().optional() }))
	.error("POST_NOT_FOUND", { status: 404 })
	.handler(({ params, query, errors }) => {
		const post = findPost(params.id);
		if (!post) throw errors.POST_NOT_FOUND();
		return respond(
			{
				...post,
				body: query.preview === "true" ? post.body.slice(0, 40) : post.body,
			},
			{ headers: { "x-powered-by": "rest-rpc" } },
		);
	});

export const router = { posts: { create, get } };
```

## Mistakes Fail to Compile

A request that doesn't match the route or a read of a field it doesn't return
is a type error, in every client of the route:


Rename a field the handler returns, and every client and query that reads it
stops compiling until it's updated. For a coding agent, `tsc` is the check
that its change is complete.

## Write Shared Logic Once

A builder holds what a group of routes shares, such as context, errors and
middleware. Every route built from it inherits them, typed:

```ts
const authenticated = route
	.$context<{ headers: Headers }>()
	.error("UNAUTHORIZED", { status: 401 })
	.use(({ context, errors, next }) => {
		const user = context.headers.get("authorization");
		if (!user) throw errors.UNAUTHORIZED();
		return next({ context: { user } });
	});

const router = {
	me: authenticated.get("/me").handler(({ context }) => context.user),
	posts: {
		create: authenticated
			.body(z.object({ title: z.string(), body: z.string() }))
			.handler(({ body, context }) => createPost(context.user, body)),
	},
};
```

## Fits What You Have

- **Just HTTP**: methods, paths, query, headers, statuses and content types
  are what they look like. Any HTTP client can call the routes.
- **Any runtime**: Bun, Deno, Cloudflare Workers and Node.
- **Any framework or none**: serve routes with `createApp`, or from Hono,
  Express, Fastify and others. Routes are the same either way.
- **Any schema library**: Zod, Valibot, ArkType or any Standard Schema.
- **Primitives over features**: authentication, caching and dependency
  injection are a few lines of middleware and context, written your way,
  instead of built-in features to configure.

## Common Questions

<Accordion>
	<AccordionItem title="Do I have to restructure my app?">
		No. Keep your authentication, database access and deployment, and your
		framework if you have one. Add typed routes at the API boundary, and adopt
		the client, TanStack Query, OpenAPI, or MCP server and agent SDK tools when
		they're useful.
	</AccordionItem>
	<AccordionItem title="Do I need a server framework?">
		No, any framework or none works. `createApp` serves routes without one, and
		any framework can serve them instead. Routes don't change, so you can switch
		later.
	</AccordionItem>
	<AccordionItem title="Can I have a separate contract?">
		Yes. Define the interface on its own, implement it on the server, and share
		it with clients. See [Contract-first](/docs/contract-first/).
	</AccordionItem>
	<AccordionItem title="What makes it good for coding agents?">
		A type check shows whether a change is complete, and the API has one obvious
		way to do each thing, so generated code looks like the docs. The skill, the
		cheatsheet and llms.txt give agents the docs of the installed version.
	</AccordionItem>
</Accordion>
