---
title: Server-Sent Events
description: Define and serve typed Server-Sent Event streams.
---

Streaming routes send Server-Sent Events (SSE). Handlers produce an async
iterable, and each yielded value becomes one event. See
[Serialization and Codecs](/docs/http-behavior/serialization#streams) for the
wire format and [Fetch Client](/docs/client/fetch-client#consume-streams) for
consuming streams.

## Define a Stream

Returning an async iterable infers a stream. Define a response with
`sse(schema)` when you want to define and validate its data schema.

```ts
import { route, sse } from "@rest-rpc/server";

const events = route
	.get("/todos/events")
	.response(sse(z.object({ id: z.string(), message: z.string() })))
	.handler(async function* () {
		yield { id: "todo_1", message: "Created" };
		yield { id: "todo_1", message: "Completed" };
	});
```

`sse(schema)` is the same as `{ "text/event-stream": schema }`. A
`text/event-stream` schema always describes the data of each event, so a status
can also offer a stream next to other
[media types](/docs/route-builder#define-media-types) by spreading
`sse(schema)` into the record, with the handler selecting one with its returned
`contentType`.

Throw a [defined error](/docs/route-builder#define-errors) before the stream
starts to respond with an error instead:

```ts
const events = route
	.get("/todos/events")
	.headers(z.object({ authorization: z.string() }))
	.response(sse(z.object({ id: z.string(), message: z.string() })))
	.error("UNAUTHORIZED", { status: 401 })
	.handler(({ headers, errors }) => {
		if (!authorize(headers.authorization)) throw errors.UNAUTHORIZED();
		return streamTodoEvents();
	});
```

Stream schemas describe event data. Event data must be JSON serializable.
Defined schemas validate each value as it is yielded. An invalid value ends
the stream instead of producing an error response.

## Add Event Metadata

Yield data directly when an event does not need metadata. Use `sseEvent()` to
add an event ID, event name, or retry hint:

```ts
import { route, sseEvent } from "@rest-rpc/server";

const events = route.get("/todos/events").handler(async function* () {
	yield { id: "todo_1", message: "Created" };
	yield sseEvent(
		{ id: "todo_1", message: "Completed" },
		{ id: "event_2", event: "todo.updated", retry: 2_000 },
	);
});
```

`sseEvent()` throws when `id` or `event` contain line breaks, or when `retry` is not
a non-negative integer number of milliseconds.

## Stop a Stream

The handler's `signal` aborts when the client disconnects. Use it to stop
producing events and release resources:

```ts
const events = route.get("/todos/events").handler(async function* ({ signal }) {
	while (!signal.aborted) {
		yield await nextTodoEvent({ signal });
	}
});
```

## Resume a Stream

A client that reconnects can send the `Last-Event-ID` header. rest-rpc does not
resume streams itself, so read the header like any other request header with
`.headers()`:

```ts
const events = route
	.get("/todos/events")
	.headers(z.object({ "last-event-id": z.string().optional() }))
	.handler(({ headers }) =>
		streamTodoEvents({ after: headers["last-event-id"] }),
	);
```

To resume streams the same way across routes, read the header in the host and
[seed the context](/docs/middleware#values-from-the-host) with it instead.

Give events an `id` with `sseEvent()` so clients have a value to resume from.
