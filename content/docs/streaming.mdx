---
title: Streaming
description: Declare and serve typed Server-Sent Event streams.
---

Streaming routes send Server-Sent Events (SSE). Handlers produce an async
iterable, and each yielded value becomes one event. See
[Serialization and Codecs](/docs/http-behavior/serialization#streams) for the
wire format and [Fetch Client](/docs/client/fetch-client#consume-streams) for
consuming streams.

## Declare a Stream

Returning an async iterable infers a stream. Use `.streamResponse()` when
you want to declare and validate its data schema.

```ts
const events = route
	.get("/todos/events")
	.streamResponse(z.object({ id: z.string(), message: z.string() }))
	.handler(async function* () {
		yield { id: "todo_1", message: "Created" };
		yield { id: "todo_1", message: "Completed" };
	});
```

`.streamResponse(schema)` is the same as
`.response({ "text/event-stream": schema })`. A `text/event-stream` schema always
describes the stream's items, so a status can also offer a stream next to other
[media types](/docs/route-builder#declare-media-types), with the handler
selecting one with its returned `contentType`.

Return an envelope when the route can return different HTTP statuses:

```ts
const events = route
	.get("/todos/events")
	.streamResponse(z.object({ id: z.string(), message: z.string() }))
	.response(z.object({ code: z.literal("UNAUTHORIZED") }), { status: 401 })
	.handler(() => ({ status: 200, body: streamTodoEvents() }));
```

Stream schemas describe event data. Event data must be JSON serializable.
Declared schemas validate each value as it is yielded. An invalid value ends
the stream instead of producing an error response.

## Add Event Metadata

Yield data directly when an event does not need metadata. Use `sse()` to add an
event ID, event name, or retry hint:

```ts
import { route, sse } from "@rest-rpc/server";

const events = route.get("/todos/events").handler(async function* () {
	yield { id: "todo_1", message: "Created" };
	yield sse({
		data: { id: "todo_1", message: "Completed" },
		id: "event_2",
		event: "todo.updated",
		retry: 2_000,
	});
});
```

`sse()` throws when `id` or `event` contain line breaks, or when `retry` is not
a non-negative integer number of milliseconds.

## Stop a Stream

The handler's `signal` aborts when the client disconnects. Use it to stop
producing events and release resources:

```ts
const events = route.get("/todos/events").handler(async function* ({ signal }) {
	while (!signal.aborted) {
		yield await nextTodoEvent({ signal });
	}
});
```

## Resume a Stream

A client that reconnects can send the `Last-Event-ID` header. rest-rpc does not
resume streams itself, so read the header like any other request header with
`.headers()`:

```ts
const events = route
	.get("/todos/events")
	.headers(z.object({ "last-event-id": z.string().optional() }))
	.handler(({ headers }) =>
		streamTodoEvents({ after: headers["last-event-id"] }),
	);
```

To resume streams the same way across routes, read the header in the host and
[seed the context](/docs/context#values-from-the-host) with it instead.

Give events an `id` with `sse()` so clients have a value to resume from.
