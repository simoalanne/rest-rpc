---
title: Fetch Client
description: Create a typed Fetch client to call your routes over HTTP.
---

`initClient()` creates a typed Fetch client from a runtime contract. When the
routes are implemented in the server, [extract a contract](/docs/client/contract-extraction) first.

```ts
import { initClient } from "@rest-rpc/core";
import { api } from "./client-contract";

const client = initClient(api, {
	baseUrl: "https://api.example.com",
});
```

The client has the same route tree shape as the contract.

## Call Routes

The route declaration determines the request and result shapes.

```ts
const created = await client.todos.create({ body: { title: "Write docs" } });
const response = await client.todos.get({ params: { id: created.body.id } });
```

A call returns a `status`-discriminated union with `contentType`, `body`, and
`headers`. `contentType` is the received base media type, or `undefined` when
the response has no content type. When a status declares several media types,
checking `contentType` narrows `body`. `headers` is a record of every response
header with lowercase names, and declared response headers are typed.

```ts
if (response.status === 200) {
	console.log(response.body.title);
}
```

A call resolves with a successful response and rejects with an error otherwise.
See [Handle Errors](#handle-errors).

### Select a Request Media Type

When a route declares several request body media types, `contentType` in the
request selects the one used to encode the body, and narrows `body` to its
schema. It is optional when the route declares one media type.

```ts
await client.todos.import({ contentType: "text/csv", body: csv });
```

## Handle Errors

A call rejects with a `RouteError` whenever a response arrived:

- A non-2xx response whose JSON body has a `code` the route
  [declares](/docs/route-builder#declare-errors) with the received status
  rejects with that error. Its `data` and declared headers are typed.
- Every other response outside the route contract rejects with
  `UNKNOWN_ERROR`: undeclared codes, including the server's
  [built-in errors](/docs/http-behavior/errors#built-in-errors), other error
  bodies such as a proxy's error page, undeclared 2xx statuses or content
  types, bodies that cannot be decoded, and
  [response validation](#response-validation) failures.

When no response arrived, such as on network failures, timeouts and aborted
requests, the call rejects with the original error instead.

```ts
import { RouteError } from "@rest-rpc/core";

try {
	await client.todos.get({ params: { id: "todo_1" } });
} catch (error) {
	if (!(error instanceof RouteError)) throw error;
	if (error.code === "TODO_NOT_FOUND") {
		console.log(error.data.id);
	} else {
		console.log(error.status, error.message, error.data);
	}
}
```

| Field     | Declared error                                    | `UNKNOWN_ERROR`                                            |
| --------- | ------------------------------------------------- | ---------------------------------------------------------- |
| `status`  | The response status                               | The response status                                        |
| `message` | The `message` of the body                         | The body's `message` when it is a string, or a generic one |
| `data`    | The `data` of the body                            | The decoded body, or `undefined` when it cannot be decoded |
| `headers` | The response headers, with declared headers typed | The response headers                                       |
| `cause`   | none                                              | Validation issues or the decoding error, when there is one |

### Safe Results

`safe()` resolves a call to an `[error, data]` tuple instead of rejecting, with
the error typed for the route:

```ts
import { safe } from "@rest-rpc/core";

const [error, response] = await safe(
	client.todos.get({ params: { id: "todo_1" } }),
);
if (error) {
	console.error(error);
} else {
	console.log(response.body.title);
}
```

Calls return a `ClientPromise`, a promise that also carries the type of its
errors. Promise methods and `async` functions return plain promises, which
`safe()` types with an `unknown` error. To keep the error type in a wrapper,
return the call directly and annotate it with `ClientPromise`.

## Consume Streams

A [streaming route](/docs/streaming) returns an async iterable of `SseEvent<T>`
values as its `body`. Application data is available on `event.data`:

```ts
export type SseEvent<T> = {
	data: T;
	id?: string;
	event?: string;
	retry?: number;
};
```

Narrow the response before iterating its body:

```ts
const response = await client.todos.events();

if (response.status === 200) {
	for await (const event of response.body) {
		console.log(event.data.message);
		console.log(event.id, event.event, event.retry);
	}
}
```

Every `text/event-stream` response is parsed as an SSE stream. Body codecs are
not consulted for it.

The initial request and later stream iteration can fail independently. Pass an
`AbortSignal` in the per-call options to cancel both the request and stream:

```ts
const controller = new AbortController();
const response = await client.todos.events(undefined, {
	signal: controller.signal,
});

controller.abort();
```

### Reconnecting

The client reads SSE events over Fetch but is not a replacement for the
browser `EventSource` API. The `id`, `event`, and `retry` fields are exposed as
metadata only: the client does not reconnect automatically, send the last event
ID, or filter events by name.

To resume a stream, send the last received event ID in the `last-event-id`
header. See [Resume a Stream](/docs/streaming#resume-a-stream) for reading it
on the server.

```ts
let lastEventId: string | undefined;

async function connect() {
	const response = await client.todos.events(undefined, {
		additionalHeaders: {
			"last-event-id": lastEventId,
		},
	});
	if (response.status !== 200) return;

	for await (const event of response.body) {
		lastEventId = event.id ?? lastEventId;
		handleTodoEvent(event.data);
	}
}
```

## Global Headers

`globalHeaders` adds headers to every request. Values can be static or provided
by synchronous or asynchronous functions. A provider is useful for values that
can change during the lifetime of the client, such as an access token.

```ts
const client = initClient(api, {
	baseUrl: "https://api.example.com",
	globalHeaders: {
		authorization: () => `Bearer ${readToken()}`,
		"x-client-version": "2026-09",
	},
});
```

A global header with a guaranteed value makes a matching declared route header
optional in client calls. A provider that can return `undefined` does not.

## Custom Fetch

If you need to wrap the fetch client with custom logic, pass a `fetch` function.

```ts
const client = initClient(api, {
	baseUrl: "https://api.example.com",
	fetch: async (url, init) => {
		const startedAt = performance.now();

		try {
			return await fetch(url, init);
		} finally {
			console.log("API request took", performance.now() - startedAt);
		}
	},
});
```

A custom `fetch` also receives the raw `Response`, for details the client
result does not keep, such as each `Set-Cookie` header from
`headers.getSetCookie()`.

## Per-Call Options

Pass fetch options as the second argument. They override matching defaults in
`fetchOptions`. Use `signal` for cancellation. `timeoutMs` still applies when a
`signal` is passed.

```ts
const response = await client.todos.get(
	{
		params: { id: "todo_1" },
		headers: { "x-request-id": "req_1" },
	},
	{
		cache: "no-store",
	},
);
```

Use `additionalHeaders` for transport headers needed only by this call. Headers
declared by the route remain part of the typed request object.

```ts
const response = await client.todos.get(
	{ params: { id: "todo_1" } },
	{
		additionalHeaders: {
			"x-trace-id": traceId,
		},
	},
);
```

If you need to pass options to a route without request input, pass `undefined` for the request input.

```ts
const response = await client.health(undefined, {
	cache: "no-store",
});
```

## Response Validation

The client decodes response bodies without schema validation by default.
Enable `validateResponses` to validate decoded bodies, declared response
headers, and stream event data:

```ts
const client = initClient(api, {
	baseUrl: "https://api.example.com",
	validateResponses: true,
});
```

The client receives the schema output on success, and a failure rejects with
an [`UNKNOWN_ERROR`](#handle-errors). The decoded response is the server's schema
output, but the client validates it as schema input. Schemas whose input and
output types differ, such as transforms, may fail on the client.

:::note
Validation requires runtime schemas, so it only applies to a
[shared contract](/docs/contract-first). [Extracted contracts](/docs/client/contract-extraction)
contain no schemas, and the option has no effect on them.
:::

## Type Helpers

Use the type helpers when a client request or result type needs to be reused,
for example in your own wrapper functions.

```ts twoslash
import type {
	InferClientError,
	InferClientRequest,
	InferClientResponse,
	InferClientStreamData,
} from "@rest-rpc/core";
import { route } from "@rest-rpc/server";
import z from "zod";

const update = route
	.patch("/todos/:id")
	.params(z.object({ id: z.string() }))
	.body(z.object({ title: z.string() }))
	.handler(({ params, body }) => ({ id: params.id, title: body.title }));

const getFirst = route
	.error("TODO_NOT_FOUND", { status: 404 })
	.handler(({ errors }) => {
		if (Math.random() < 0.5) throw new errors.TODO_NOT_FOUND();
		return { id: "todo_1", title: "Write docs" };
	});

type UpdateTodoRequest = InferClientRequest<typeof update>;

type GetFirstTodoResponse = InferClientResponse<typeof getFirst>;

type GetFirstTodoError = InferClientError<typeof getFirst>;

const events = route
	.get("/todos/events")
	.streamResponse(z.object({ id: z.string(), message: z.string() }))
	.handler(async function* () {
		yield { id: "todo_1", message: "Created" };
	});

type TodoEvent = InferClientStreamData<typeof events>;
```

| Type                                       | Infers                                                                                   |
| ------------------------------------------ | ---------------------------------------------------------------------------------------- |
| `InferClientRequest<Route, GlobalHeaders>` | The request passed to the route call, or `undefined` for routes without input.           |
| `InferClientResponse<Route>`               | Every response envelope of the route.                                                    |
| `InferClientError<Route>`                  | The declared errors of the route and `UNKNOWN_ERROR`.                                    |
| `InferClientStreamData<Route>`             | The `data` of each event from a [streaming route](#consume-streams), without `SseEvent`. |

Calls reject with `InferClientError<Route>` when a response arrived, and with
other `Error`s otherwise.

`InferClientRequest` accepts the type of your `globalHeaders` as a second
argument, so headers that `globalHeaders` always provides become optional:

```ts
import type { InferClientRequest } from "@rest-rpc/core";
import type { api } from "./client-contract";

const globalHeaders = { authorization: () => `Bearer ${getToken()}` };

type UpdateTodoRequest = InferClientRequest<
	typeof api.todos.update,
	typeof globalHeaders
>;
```

`ApiClientFor<typeof api>` is the type of the whole client created from a
contract.

Each helper also accepts a route tree and infers a matching tree of types, so
one exported type covers every route:

```ts
import type { InferClientResponse } from "@rest-rpc/core";
import type { api } from "./client-contract";

export type ClientResponses = InferClientResponse<typeof api>;

type TodoResponse = ClientResponses["todos"]["get"];
```
