---
title: Local Client
description: Call route handlers in-process with call or createLocalClient.
---

A local call runs the same route pipeline as an HTTP request:

1. The input is validated with the route's request schemas.
2. The route's middleware and handler run.
3. The handler output is validated with the route's response schemas.

The steps that only exist for HTTP are skipped: body decoding, request content
type checks, and response serialization. The result is the
validated output, not an encoded `Response`.

## One-off Calls

Use `call()` to invoke single route handler without creating a [Local Client](/docs/client/local-client#local-client).

```ts twoslash
import { call, route } from "@rest-rpc/server";
import z from "zod";

const getTodo = route
	.get("/todos/{id}")
	.params(z.object({ id: z.coerce.number<string>() }))
	.handler(({ params }) => ({ id: params.id, title: "Write docs" }));

const response = await call(getTodo, { params: { id: "1" } });
```

`call()` takes the same request and returns the same response as a
[Fetch client](/docs/client/fetch-client) call. Request segments are schema
inputs, the values a client would send, and handlers receive the schema output.
A request body media type is selected with `contentType` in the request, as in a
[Fetch client call](/docs/client/fetch-client#select-a-request-media-type).

The optional third argument replaces what an HTTP request would otherwise provide:

| Option    | Description                                                                                                     |
| --------- | --------------------------------------------------------------------------------------------------------------- |
| `signal`  | Passed to the handler. Defaults to a signal that never aborts.                                                  |
| `context` | The [initial context](/docs/middleware#values-from-the-host) the route declares. Required when it declares any. |

### Errors

A local call rejects like a [Fetch client call](/docs/client/fetch-client#typesafe-error-handling),
so [`safe()`](/docs/client/fetch-client#with-safe) works with it too:

- A thrown error the route defines rejects with that error as defined, after
  its `data` is validated.
- A defined error whose `data` fails validation rejects with the
  `INTERNAL_SERVER_ERROR` that would be sent.
- A `RouteError` with a code the route does not define, including
  [built-in errors](/docs/http-behavior/errors#built-in-errors), rejects as
  thrown.
- Other errors thrown by the handler reject unchanged.

## Local Client

When you want to call several routes or create a reusable client, `createLocalClient()` creates one that mirrors the route tree.
It is the local equivalent of the [Fetch client](/docs/client/fetch-client).

```ts
import { createLocalClient } from "@rest-rpc/server";
import { routes } from "./routes";

const client = createLocalClient(routes);

const created = await client.todos.create({ body: { title: "Write docs" } });
const response = await client.todos.get(
	{ params: { id: created.body.id } },
	{ context: { user: { id: "user_1" } } },
);
```
