---
title: Route Builder
description: Define HTTP routes with request segments, typed responses, errors, and streams.
---

A route declares its method and path, the request it reads, the responses it
returns and the errors it throws. Schemas are any
[Standard Schema](/docs/http-behavior/validation), or `type<T>()` for types
alone.

## Start with Defaults

```ts
import { route } from "@rest-rpc/server";
import { z } from "zod";

const create = route
	.body(z.object({ title: z.string() }))
	.handler(({ body: { title } }) => ({ id: crypto.randomUUID(), title }));

export const routes = { todos: { create } }; // POST /todos/create
```

Without a method, a route is `POST`, and without a path, its path is its keys
in the route tree. A returned value is a JSON body with status `200`. Route
trees are plain objects, so group them into modules and compose them where
they're served or given to a client.

## Choose a Method and Path

```ts
const search = route
	.get("/todos/search")
	.query(z.object({ term: z.string() }))
	.handler(({ query }) => searchTodos(query.term));

const getTodo = route
	.get("/todos/:id")
	.handler(({ params }) => findTodo(params.id)); // params: { id: string }

const listTodos = route.get().handler(() => listTodos()); // GET, path from its tree keys
```

The methods are `.get()`, `.post()`, `.put()`, `.patch()` and `.delete()`,
once per route. `:name` segments are string params unless `.params()` defines
them. Wildcards and regular expressions aren't supported.

## Path Prefixes

`.prefix()`, called before the method, prepends a path to every route built
from it. Prefixes are part of the route, so clients and OpenAPI use the full
path:

```ts
const tenant = route
	.prefix("/tenants/:tenant")
	.params(z.object({ tenant: z.string() }));

const getTodo = tenant
	.get("/todos/:id") // GET /tenants/:tenant/todos/:id
	.params(z.object({ id: z.coerce.number<number>() }))
	.handler(({ params }) => findTodo(params.tenant, params.id));
```

Params are all inferred or all defined: once a route has a `.params()`
schema, its schemas have to cover every segment, the prefix's included.

## Request Segments

```ts
const update = route
	.patch("/todos/:id")
	.params(z.object({ id: z.string() }))
	.query(z.object({ notify: z.stringbool().optional() }))
	.headers(z.object({ "x-request-id": z.string().optional() }))
	.body(z.object({ title: z.string() }))
	.handler(({ params, query, headers, body }) =>
		updateTodo(params.id, body.title, {
			notify: query.notify,
			requestId: headers["x-request-id"],
		}),
	);
```

- `.params()` keys can't be optional, and a route with params needs `:name`
  segments for them.
- `GET` routes have no `.body()`.
- Header names are lowercase, and an uppercase name is a type error.
- Each segment can be called more than once. Every schema validates the
  original value, and their outputs are shallow-merged, so each has to output
  an object, and a strict schema such as `z.strictObject()` would reject the
  other schemas' keys:

```ts
const base = route.body(z.object({ title: z.string() }));
const create = base
	.body(z.object({ description: z.string().optional() }))
	.handler(({ body }) => createTodo(body.title, body.description));
```

See [Encoding and Content Types](/docs/http-behavior/encoding) for what each
segment receives, and for bodies other than JSON.

## Return Responses

A handler returns the response body, or `respond()` for the rest of the
response:

```ts
const create = route
	.post("/todos")
	.body(z.object({ title: z.string() }))
	.handler(({ body, respond }) => {
		const todo = createTodo(body.title);
		return respond(todo, {
			status: 201, // 200 to 299
			headers: { location: `/todos/${todo.id}` },
			cookies: ["seen=1; HttpOnly"], // each its own Set-Cookie header
		});
	});
```

- `undefined` is a response without a body.
- An async iterable is a [stream](/docs/streaming).
- A Fetch `Response` is sent as it is: see [Raw Responses](#raw-responses).
- Anything else is a JSON body, a `status` field included, since only
  `respond()` results are read as responses.

Without `.response()`, the statuses and bodies the handler returns are the
client's result type. Errors are [thrown](#define-errors), not returned.

## Define Responses

`.response(schema, options)` defines a response and validates it at runtime:

```ts
route
	.post("/todos")
	.body(z.object({ title: z.string() }))
	.response(todoSchema, {
		status: 201,
		headers: z.object({ location: z.string() }),
	})
	.response({ status: 202 }) // no body
	.handler(({ body, respond }) => {
		if (isQueued(body)) return respond(undefined, { status: 202 });
		const todo = createTodo(body.title);
		return respond(todo, {
			status: 201,
			headers: { location: `/todos/${todo.id}` },
		});
	});
```

- `status` defaults to `200`, and each status is defined once.
- A plain return value is the body of the only defined response. With several,
  `respond()` takes one of the defined statuses.
- `headers` works on every response, bodyless and stream ones included.

## Raw Responses

Return a Fetch `Response` for anything the builder can't describe, such as a
redirect or a legacy format. The request is still validated and middleware
still runs, but the response is sent as it is, without validation or codecs:

```ts
route
	.get("/files/:id/download")
	.handler(async ({ params }) =>
		Response.redirect(await signedUrl(params.id), 302),
	);
```

- The client gets `status: number` and `body: unknown`, decoded by the
  received content type. A handler that returns a `Response` on some paths
  makes the whole route loosely typed. Defined errors stay typed.
- Middleware sees the `Response` as the `body` of the response `next()`
  resolves to. Its `status`, `headers` and `cookies` are what's sent, so
  middleware that adds a header works on raw routes too.
- To declare a raw route in a [contract](/docs/contract-first), use
  `.response(raw({ description }))` as its only response. OpenAPI documents it
  as `default`.

## Static Responses

`.static(value)` completes a route with a response that is the same for every
request. It's validated and serialized once, when the routes are compiled:

```ts
route.get("/health").static({ ok: true });
route
	.get("/robots.txt")
	.static(
		respond("User-agent: *", { headers: { "content-type": "text/plain" } }),
	);
```

- It skips [interceptors](/docs/server/interceptors) and middleware, so it's for
  public content. Put headers such as CORS in the response itself, and use
  `.handler()` for anything that needs access control.
- It can't be a function, promise or stream, and the route can't read the
  request or have middleware.
- Its schemas and codecs have to be synchronous, since compiling is.

## Define Errors

Errors are thrown. `.error(code, options)` defines one, and handlers and
middleware receive it in `errors`:

```ts
const get = route
	.get("/todos/:id")
	.params(z.object({ id: z.string() }))
	.response(todoSchema)
	.error("TODO_NOT_FOUND", { status: 404, data: z.object({ id: z.string() }) })
	.handler(({ params, errors }) => {
		const todo = findTodo(params.id);
		if (!todo) throw errors.TODO_NOT_FOUND({ data: { id: params.id } });
		return todo;
	});
```

| Option        | Default  | Description                                     |
| ------------- | -------- | ----------------------------------------------- |
| `status`      | `400`    | 400 to 599                                      |
| `data`        | none     | Schema of the error's `data`                    |
| `headers`     | none     | Schema of its response headers                  |
| `message`     | the code | Default message, replaced when thrown           |
| `description` | none     | Describes the error in [OpenAPI](/docs/openapi) |

To throw an error outside handlers, define it once with `routeError()`, add it
to routes, and throw it with `new` anywhere:

```ts
import { route, routeError } from "@rest-rpc/server";

export const TodoNotFound = routeError("TODO_NOT_FOUND", {
	status: 404,
	data: z.object({ id: z.string() }),
});

export const findTodo = (id: string) => {
	const todo = todos.get(id);
	if (!todo) throw new TodoNotFound({ data: { id } });
	return todo;
};

const get = route
	.get("/todos/:id")
	.error(TodoNotFound)
	.handler(({ params }) => findTodo(params.id));
```

Adding the same definition twice, such as on a base and a route, is fine, and
a different error with the same code throws. Defining errors doesn't define
responses. See [Errors](/docs/http-behavior/errors) for what's sent, and for
errors a route doesn't define.

## Return Streams

Returning an async iterable sends Server-Sent Events. `sse(schema)` defines
and validates the data of each event:

```ts
const events = route
	.get("/todos/events")
	.response(sse(z.object({ id: z.string(), message: z.string() })))
	.handler(() => streamTodoEvents());
```

See [Server-Sent Events](/docs/streaming).

## Metadata and OpenAPI

`.meta()` attaches [metadata](/docs/middleware#metadata) of the shape
`$meta<T>()` declares, and `.openAPI()` describes the operation:

```ts
const list = route
	.$meta<{ access: "public" | "signed-in" }>()
	.get("/todos")
	.meta({ access: "signed-in" })
	.openAPI({ summary: "List todos", tags: ["Todos"] })
	.handler(() => listTodos());
```

Both can be called more than once: metadata is shallow-merged, and OpenAPI
details are merged with tags combined.

## Reuse Builders

Every builder method returns a new route, so a partial route is a base that
other routes share without affecting each other:

```ts
const authenticated = route
	.headers(z.object({ authorization: z.string() }))
	.error("UNAUTHORIZED", { status: 401 });

const list = authenticated.get("/todos").handler(() => listTodos());
const remove = authenticated
	.delete("/todos/:id")
	.response({ status: 204 })
	.handler(({ params }) => {
		deleteTodo(params.id);
	});
```

## Handler Arguments

- `params`, `query`, `headers` and `body`: the validated request.
- `context`: initial values from the host and values middleware adds. See
  [Context](/docs/middleware#context).
- `route`: the route's definition, with its method, path and `meta`.
- `errors`: the [defined errors](#define-errors).
- `respond`: see [Return Responses](#return-responses).
- `signal`: aborts when the client disconnects.

Native request objects aren't passed. To use them,
[put them in the context](/docs/middleware#values-from-the-host).

## Type Helpers

The type helpers give a route's types to code outside it, such as services or
handlers written separately. Infer from a route before `.handler()`, or from a
contract route: a completed route's type depends on its handler. Each helper
also takes a route tree:

```ts
import type { InferServerRequest } from "@rest-rpc/server";
import type { routes } from "./routes";

type CreateTodoRequest = InferServerRequest<typeof routes>["todos"]["create"];
```

### Infer Server Request

The object a handler receives, with every [argument](#handler-arguments):

```ts twoslash
import type { InferServerRequest } from "@rest-rpc/server";
import { route } from "@rest-rpc/server";
import z from "zod";

const updateDefinition = route
	.patch("/todos/:id")
	.params(z.object({ id: z.string() }))
	.body(z.object({ title: z.string() }));

type UpdateTodoRequest = InferServerRequest<typeof updateDefinition>;

const updateTodo = ({ params, body }: UpdateTodoRequest) => ({
	id: params.id,
	title: body.title,
});

const update = updateDefinition.handler(updateTodo);
```

### Infer Server Response

What a handler can return for the responses `.response()` defines. Inferred
responses have nothing to infer before `.handler()`:

```ts twoslash
import type { InferServerResponse } from "@rest-rpc/server";
import { respond, route } from "@rest-rpc/server";
import z from "zod";

const todoSchema = z.object({ id: z.string(), title: z.string() });

const createDefinition = route
	.post("/todos")
	.body(z.object({ title: z.string() }))
	.response(todoSchema, { status: 201 })
	.response({ status: 202 });

type CreateTodoResponse = InferServerResponse<typeof createDefinition>;

const createTodo = (title: string): CreateTodoResponse =>
	title.length > 100
		? respond(undefined, { status: 202 })
		: respond({ id: "todo_1", title }, { status: 201 });

const create = createDefinition.handler(({ body }) => createTodo(body.title));
```

### Infer Server Handler

The full handler signature, to write a handler apart from its definition:

```ts twoslash
import { route, type InferServerHandler } from "@rest-rpc/server";
import z from "zod";

const todoSchema = z.object({ id: z.string(), title: z.string() });

const getDefinition = route
	.get("/todos/:id")
	.params(z.object({ id: z.string() }))
	.response(todoSchema)
	.error("TODO_NOT_FOUND", { status: 404 });

const getTodo: InferServerHandler<typeof getDefinition> = ({
	params,
	errors,
}) => {
	if (params.id !== "todo_1") throw errors.TODO_NOT_FOUND();
	return { id: params.id, title: "Write docs" };
};

const get = getDefinition.handler(getTodo);
```
