title: Quickstart
description: Define HTTP routes with handlers and call them through a typed client.
---

`rest-rpc` builds REST APIs with RPC-like ergonomics: an HTTP route builder
with sensible defaults, and a typed client to call the routes.

This guide uses Bun and Zod to build two routes: a minimal create operation
and a GET with path params, query input, and a declared error. Their response
types are inferred from the handlers.

Same code runs on other fetch-native runtimes such as Deno and Cloudflare Workers.
See the [Fetch Runtime](/docs/server/fetch) for details, [Node HTTP](/docs/server/node) for `node:http`,
and [Framework Integration](/docs/server/framework-integration) to add the routes to an existing framework.

## Install

```package-install
npm i @rest-rpc/core @rest-rpc/server zod
```

## Define Routes

```ts routes.ts
import { route } from "@rest-rpc/server";
import { z } from "zod";

type Todo = { id: string; title: string; completed: boolean };
const todos = new Map<string, Todo>();

const create = route
	.body(z.object({ title: z.string().min(1) }))
	.handler(({ body: { title } }) => {
		const todo: Todo = {
			id: crypto.randomUUID(),
			title,
			completed: false,
		};
		todos.set(todo.id, todo);
		return todo;
	});

const get = route
	.get("/todos/:id")
	.params(z.object({ id: z.string() }))
	.query(z.object({ uppercase: z.enum(["yes", "no"]).optional() }))
	.error("TODO_NOT_FOUND", { status: 404 })
	.handler(({ params, query, errors }) => {
		const todo = todos.get(params.id);
		if (!todo) throw errors.TODO_NOT_FOUND();
		return {
			...todo,
			title: query.uppercase === "yes" ? todo.title.toUpperCase() : todo.title,
		};
	});

export const routes = { todos: { create, get } };
```

`todos.create` uses `POST /todos/create`, reads a JSON body, and returns the
todo as a 200 response. `todos.get` uses `GET /todos/:id?uppercase=yes` and
returns the todo with status 200, or responds with the `TODO_NOT_FOUND` error
and status 404.

The request schemas validate inputs, and the handler's return value determines
the client's result type.

## Register Routes

```ts server.ts
import { createApp } from "@rest-rpc/server";
import { routes } from "./routes";

Bun.serve({ ...createApp(routes), port: 3000 });
```

`createApp` returns an app that `Bun.serve()` serves directly, routing the
requests with Bun's native router. To add the routes to an existing framework
instead, see [Framework Integration](/docs/server/framework-integration).

## Create the Client

Extract a minimal contract from the routes with a
[Bun macro](https://bun.com/docs/bundler/macros). The macro runs at bundle time
and inlines the contract into the client, so no server code is shipped:

```ts client-contract.ts
import { extractContract } from "@rest-rpc/core";
import { routes } from "./routes";

export function getApi() {
	return extractContract(routes);
}
```

See [Client Contract Extraction](/docs/client/contract-extraction) for other
bundler setups.

## Call the Routes

```ts client.ts
import { createClient, isDeclaredError, safe } from "@rest-rpc/core";
import { getApi } from "./client-contract" with { type: "macro" };

const client = createClient(getApi(), { baseUrl: "http://localhost:3000" });

const created = await client.todos.create({ body: { title: "Write docs" } });
const result = await safe(
	client.todos.get({
		params: { id: created.body.id },
		query: { uppercase: "yes" },
	}),
);

if (!result.error) {
	console.log(result.data.body.title);
} else if (
	isDeclaredError(result.error) &&
	result.error.code === "TODO_NOT_FOUND"
) {
	console.log(result.error.message);
}
```

Calls reject with errors, and `safe()` returns them as values instead. See
[Handle Errors](/docs/client/fetch-client#typesafe-error-handling).

The calls are typed functions, while the requests still use the methods, URLs,
query parameters, and statuses you defined. Other HTTP clients can call the same
endpoints.
