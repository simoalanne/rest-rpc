title: Quickstart
description: Define HTTP routes with handlers and call them through a typed client.
---

`rest-rpc` builds REST APIs with RPC-like ergonomics: an HTTP route builder
with sensible defaults, and a typed client to call the routes.

This guide uses Bun and Zod to build two routes: a minimal create operation
and a GET with path params, query input, and a defined error. Their response
types are inferred from the handlers.

Same code runs on other fetch-native runtimes such as Deno and Cloudflare Workers.
See [Serving Routes](/docs/server/overview) for the ways to serve the routes, on Fetch runtimes,
on [Node](/docs/server/node), or from an existing [framework](/docs/server/framework-integration).

## Install

```package-install
npm i @rest-rpc/core @rest-rpc/server zod
```

## Define Routes

```ts router.ts
import { route } from "@rest-rpc/server";
import * as z from "zod";

type Post = { id: string; title: string; body: string };
const posts = new Map<string, Post>();

const create = route
	.body(z.object({ title: z.string().min(1), body: z.string() }))
	.handler(({ body: { title, body } }) => {
		const post: Post = {
			id: crypto.randomUUID(),
			title,
			body,
		};
		posts.set(post.id, post);
		return post;
	});

const get = route
	.get("/posts/:id")
	.params(z.object({ id: z.string() }))
	.query(z.object({ preview: z.enum(["true", "false"]).optional() }))
	.error("POST_NOT_FOUND", { status: 404 })
	.handler(({ params, query, errors }) => {
		const post = posts.get(params.id);
		if (!post) throw errors.POST_NOT_FOUND();
		return {
			...post,
			body: query.preview === "true" ? post.body.slice(0, 40) : post.body,
		};
	});

export const router = { posts: { create, get } };
```

`posts.create` uses `POST /posts/create`, reads a JSON body, and returns the
post as a 200 response. `posts.get` uses `GET /posts/:id?preview=true` and
returns the post with status 200, or responds with the `POST_NOT_FOUND` error
and status 404. The body is cut to 40 characters when `preview` is true.

The request schemas validate inputs, and the handler's return value determines
the client's result type.

## Register Routes

```ts server.ts
import { createApp } from "@rest-rpc/server";
import { router } from "./router.ts";

export default createApp(router);
```

Run it with `bun server.ts`, which serves it on port 3000. To add the routes to
an existing framework instead, see
[Framework Integration](/docs/server/framework-integration).

## Create the Client

Extract a minimal contract from the routes with a
[Bun macro](https://bun.com/docs/bundler/macros). The macro runs at bundle time
and inlines the contract into the client, so no server code is shipped:

```ts contract.ts
import { extractContract } from "@rest-rpc/core";
import { router } from "./router.ts";

export function getContract() {
	return extractContract(router);
}
```

Vite and other bundlers run the same macro with `unplugin-macros`. See
[Client Contract Extraction](/docs/client/contract-extraction#extract-routes-with-a-macro).

## Call the Routes

```ts client.ts
import { createClient, isDefinedError, safe } from "@rest-rpc/core";
import { getContract } from "./contract" with { type: "macro" };

const client = createClient(getContract(), { origin: "http://localhost:3000" });

const created = await client.posts.create({
	body: { title: "Hello", body: "First post" },
});
const result = await safe(
	client.posts.get({
		params: { id: created.body.id },
		query: { preview: "true" },
	}),
);

if (!result.error) {
	console.log(result.data.body.title);
} else if (
	isDefinedError(result.error) &&
	result.error.code === "POST_NOT_FOUND"
) {
	console.log(result.error.message);
}
```

Calls reject with errors, and `safe()` returns them as values instead. See
[Handle Errors](/docs/client/fetch-client#typesafe-error-handling).

The calls are typed functions, while the requests still use the methods, URLs,
query parameters, and statuses you defined. Other HTTP clients can call the same
endpoints.
