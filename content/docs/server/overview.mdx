title: Serving Routes
description: Choose how much of each request rest-rpc handles, on Fetch or Node
---

`@rest-rpc/server` serves routes with Fetch `Request` and `Response`, on
runtimes such as Bun, Deno and Cloudflare Workers. `@rest-rpc/server/node`
serves them with Node's `IncomingMessage` and `ServerResponse`, reading and
writing them directly. Both export the same functions, and routes behave the
same on both.

```package-install
npm i @rest-rpc/server
```

## Choosing a Level

The functions differ in how much of each request rest-rpc handles:

|                     | `createRouteHandlers`                       | `createCatchAllHandler`               | `createApp`                           |
| ------------------- | ------------------------------------------- | ------------------------------------- | ------------------------------------- |
| Routing             | The framework, one route per rest-rpc route | rest-rpc, under one framework route   | rest-rpc                              |
| Unmatched requests  | Not routed to rest-rpc                      | Left to the host, as `matched: false` | A `NOT_FOUND` error                   |
| Other thrown errors | Reject, for the host to handle              | Reject, for the host to handle        | `INTERNAL_SERVER_ERROR`               |
| Initial context     | Per request                                 | Per request                           | A value, or a function of the request |
| Returns             | Routes to register                          | A handler to mount                    | The handler the runtime calls         |

- Use [`createApp`](#create-app) when rest-rpc serves every request.
- Use the [catch-all handler](/docs/server/framework-integration#catch-all-handler)
  to add the routes to a framework under one route, such as `/api/*`.
- Use [route handlers](/docs/server/framework-integration#native-router) when
  the framework should see each route, such as to apply its middleware per
  route.

### Create App

`createApp` returns the function the runtime calls for each request, and
doesn't start a server:

```ts server.ts
import { createApp } from "@rest-rpc/server";
import { router } from "./router.ts";

export default createApp(router);
```

See [Fetch](/docs/server/fetch) and [Node](/docs/server/node) for each
runtime, and [Framework Integration](/docs/server/framework-integration) for
the other two.

## Route Options

Every function takes these options after the route tree:

```ts
type CreateRouteHandlersOptions = {
	/** Codecs for other body formats, selected before the built-in ones. */
	bodyCodecs?: readonly BodyCodec[];
	/** Skips request validation. The types stay as if the schemas ran. */
	disableRequestValidation?: boolean;
	/** Skips response validation. The types stay as if the schemas ran. */
	disableResponseValidation?: boolean;
	/** The data format, keepalive and initial comment of event streams. */
	sse?: SseOptions;
};
```

See [Custom Codecs](/docs/http-behavior/encoding#custom-codecs) for `bodyCodecs`,
[Disabling Validation](/docs/http-behavior/validation#disabling-validation) for
the validation options, and [Data Format](/docs/server-sent-events#data-format) and
[Stream Options](/docs/server-sent-events#stream-options) for `sse`.

## Paths

Path params are written as `:name`. Matching follows
[rou3](https://github.com/h3js/rou3): static segments take precedence over
params, and one trailing slash is ignored. Param values are percent-decoded.

### Mount Path

`createApp` and the catch-all handler take a `mountPath`, such as `/api`, to
serve the routes under. Requests outside it are unmatched, and it is removed
from the request path before matching. Route paths do not include it, so
clients pass the same `mountPath`. A path that clients and OpenAPI documents
should include in each route, such as `/v1`, belongs in the routes instead,
defined with [`.prefix()`](/docs/route-builder#path-prefixes).
