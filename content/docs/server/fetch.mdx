`@rest-rpc/server` serves routes with Fetch `Request` and `Response`, on
fetch-native runtimes such as Bun, Deno, and Cloudflare Workers. See
[Serving Routes](/docs/server/overview) for what is shared with
[Node](/docs/server/node), and [Framework Integration](/docs/server/framework-integration)
to add the routes to a framework such as Hono.

## Usage

`createApp` turns a route tree into an app with a `fetch` handler. Runtimes such
as Bun, Deno, and Cloudflare Workers serve it when it is the default export. The
app also has `routes` in the format of Bun's `routes` server option, so on Bun
the requests are routed by Bun's native router:

```ts server.ts
import { createApp, route } from "@rest-rpc/server";
import { z } from "zod";

const todos = new Map([["todo_1", { id: "todo_1", title: "Write docs" }]]);

const getTodo = route
	.get("/todos/:id")
	.params(z.object({ id: z.string() }))
	.error("TODO_NOT_FOUND", { status: 404 })
	.handler(({ params, errors }) => {
		const todo = todos.get(params.id);
		if (!todo) throw errors.TODO_NOT_FOUND();
		return todo;
	});

export const routes = { todos: { get: getTodo } };

export default createApp(routes);
```

:::tip[Bun Server Options]
To set other Bun server options, spread the app into `Bun.serve()`, and spread
`app.routes` to add your own routes:

```ts server.ts
const app = createApp(routes);

Bun.serve({
	...app,
	port: 8080,
	routes: { ...app.routes, "/health": new Response("ok") },
});
```

:::

## App Options

`createApp` takes the [route options](/docs/server/overview#route-options) and
these:

```ts
type CreateAppOptions = {
	mountPath?: AbsolutePath;
	// Required when the routes declare initial context.
	context?:
		| TContext
		| ((request: Request, ...args: TArgs) => TContext | Promise<TContext>);
	interceptors?: readonly Interceptor[];
};
```

- `mountPath`: the path the routes are served under, such as `/api`. See
  [Mount Path](/docs/server/overview#mount-path).
- `context`: the [initial context](/docs/middleware#values-from-the-host) the
  routes declare, or a function, sync or async, that returns it for each
  request. It is required when the routes declare initial context, and must
  satisfy the initial context of every route. If the function throws, the
  response is an `INTERNAL_SERVER_ERROR`.

  ```ts
  createApp(routes, {
  	context: async (request) => ({ db, headers: request.headers }),
  });
  ```

  The function also receives what the runtime passes to `fetch` after the
  request, such as the `env` bindings of Cloudflare Workers or the connection
  info of Deno. Their types are inferred from the function's parameters:

  ```ts
  export default createApp(routes, {
  	context: (request, env: Env) => ({ db: env.DB }),
  }) satisfies ExportedHandler<Env>;
  ```

- `interceptors`: functions around everything the app does for a request. See
  [Interceptors](#interceptors).

Errors a route does not send as an error response, such as errors thrown by
handlers, are sent as
[`INTERNAL_SERVER_ERROR`](/docs/http-behavior/errors#built-in-errors) responses,
and requests that match no route as
[`NOT_FOUND`](/docs/http-behavior/errors#built-in-errors) errors.

## Interceptors

An interceptor wraps everything the app does for a request, for work that
has to happen before routing or on every response, such as API key checks,
request IDs, logging, or CORS. Create one with `interceptor()`, which types the
function and returns it unchanged:

```ts
import { createApp, interceptor } from "@rest-rpc/server";

const apiKey = interceptor(({ request, next }) =>
	request.headers.get("x-api-key") === API_KEY
		? next()
		: new Response("Forbidden", { status: 403 }),
);

const timing = interceptor(async ({ next, route }) => {
	const started = performance.now();
	const response = await next();
	// The route path, such as `/todos/:id`, keeps metric labels bounded.
	metrics.record(route?.path ?? "unmatched", performance.now() - started);
	return response;
});

export default createApp(routes, { interceptors: [timing, apiKey] });
```

- Interceptors run in order, the first outermost, and the app's own handling
  is innermost.
- They receive every request, including ones that match no route and
  `OPTIONS` preflights, and the app's `routes` for Bun run them too.
- [Static routes](/docs/route-builder#static-responses) skip them, since their
  response is prebuilt. Static routes are for public content, so complete a
  route with `.handler()` when it needs access control, and put headers such
  as CORS in the static response itself.
- `route` is the matched route's definition, with its path and
  [`meta`](/docs/middleware#metadata), or `undefined` when no route matches.
- `args` are the arguments the runtime passed to `fetch` after the request,
  such as the `env` of Cloudflare Workers. They are untyped, so narrow them
  where they are read: `const [env] = args as [Env]`.
- `next()` continues with the later interceptors and the app. It resolves
  with the response, error responses included, and rejects only for bugs. See
  [What `next()` Returns](#what-next-returns). It may be called more than
  once, such as to retry.
- An error an interceptor throws is sent as an
  [`INTERNAL_SERVER_ERROR`](/docs/http-behavior/errors#built-in-errors)
  response.

`next(request)` continues with another request, such as one with other
headers. The matched route reads it, but routing isn't repeated, so changing
its URL or method isn't supported. Wrap `fetch` to rewrite where a request is
routed:

```ts
const app = createApp(routes);

export default {
	fetch: (request: Request) => app.fetch(rewrite(request)),
};
```

Interceptors are about HTTP, not routes, so they are untyped. Per-route logic
with typed context belongs in [middleware](/docs/middleware), which runs after
request validation.

### Not Found

The app matches the route before the interceptors run. When no route
matches, `route` is `undefined`, and calling `next()` would resolve with the
app's `NOT_FOUND` error response. An interceptor that sends its own response
instead doesn't call `next()`:

```ts
const notFound = interceptor(({ route, next }) =>
	route ? next() : new Response("Not found", { status: 404 }),
);
```

### What `next()` Returns

| What happens in the app                                                                                                                             | `next()`                                          |
| --------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------- |
| The route returns a response                                                                                                                        | Resolves with it                                  |
| A `RouteError` is thrown: a [defined or built-in error](/docs/http-behavior/errors), such as a request validation failure or a handler's `NotFound` | Resolves with its JSON error response             |
| No route matches, so `route` is `undefined`                                                                                                         | Resolves with the `NOT_FOUND` JSON error response |
| Anything else is thrown, such as an `Error` from a handler, middleware, the `context` function or a codec                                           | Rejects with the thrown value, unchanged          |

Every outcome the contract describes, including errors, arrives as a response
whose status you can read. A rejection only ever means a bug. When nothing
catches it, the app sends an `INTERNAL_SERVER_ERROR` response.

So error reporting is a `try`/`catch` around `next()`:

```ts
const logErrors = interceptor(async ({ request, next }) => {
	try {
		return await next();
	} catch (error) {
		// The thrown value as is, such as an `Error` with its stack and `cause`.
		console.error(request.method, request.url, error);
		throw error; // The app sends INTERNAL_SERVER_ERROR.
	}
});
```

`next()` resolves before the response body streams, so a stream that fails
later can't be caught here. The stream ends, and the client receives an
incomplete response.

### Error Responses

`errorResponse(error)` creates the `Response` the app sends for a
`RouteError`: its status and headers, and a JSON `{ code, message, data? }`
body. The [client](/docs/client/fetch-client) decodes that response as a
`RouteError`, so an error an interceptor sends is handled like any other. No
route definition applies, so the error is sent with its own status, `data`
and headers, without validation:

```ts
import { errorResponse, interceptor, routeError } from "@rest-rpc/server";

const RateLimited = routeError("RATE_LIMITED", { status: 429 });

const rateLimit = interceptor(({ request, next }) =>
	limiter.allow(request) ? next() : errorResponse(new RateLimited()),
);
// The client rejects with a RouteError whose code is "RATE_LIMITED".
```

### CORS

CORS headers have to be on every response, error responses included, or the
browser hides the response from the client, and preflights have to be
answered before routing. One interceptor does both.

When `next()` rejects, the app creates its `INTERNAL_SERVER_ERROR` response
after the interceptors, so headers they add can't be on it. The interceptor
creates that response itself instead, with `errorResponse()`, so it gets the
headers too:

```ts
import {
	errorResponse,
	interceptor,
	InternalServerError,
} from "@rest-rpc/server";

const cors = interceptor(async ({ request, next }) => {
	const headers = {
		"access-control-allow-origin": "https://app.example.com",
		vary: "Origin",
	};
	if (request.method === "OPTIONS") {
		return new Response(null, {
			status: 204,
			headers: {
				...headers,
				"access-control-allow-methods": "GET, POST, PUT, PATCH, DELETE",
				"access-control-allow-headers": "content-type, authorization",
			},
		});
	}
	let response: Response;
	try {
		response = await next(); // Every RouteError arrives here as a response.
	} catch {
		// Only bugs get here: the response the app would send, with the headers.
		response = errorResponse(new InternalServerError());
	}
	// A returned `Response` may have immutable headers, so it is copied.
	const copy = new Response(response.body, response);
	for (const [name, value] of Object.entries(headers)) {
		copy.headers.set(name, value);
	}
	return copy;
});
```
