---
title: Fetch Runtime
description: Serve rest-rpc routes with Fetch Request and Response
---

The Fetch runtime serves rest-rpc routes with Fetch `Request` and `Response`,
on fetch-native runtimes such as Bun, Deno, and Cloudflare Workers. For
`node:http`, see [Node HTTP](/docs/server/node). To add the routes to an
existing framework such as Hono or Express, see
[Framework Integration](/docs/server/framework-integration).

## Install

```package-install
npm i @rest-rpc/server
```

## Usage

`createApp` turns a route tree into an app with a `fetch` handler. Runtimes such
as Bun, Deno, and Cloudflare Workers serve it when it is the default export:

```ts server.ts
import { createApp, route } from "@rest-rpc/server";
import { z } from "zod";

const todos = new Map([["todo_1", { id: "todo_1", title: "Write docs" }]]);

const getTodo = route
	.get("/todos/:id")
	.params(z.object({ id: z.string() }))
	.error("TODO_NOT_FOUND", { status: 404 })
	.handler(({ params, errors }) => {
		const todo = todos.get(params.id);
		if (!todo) throw errors.TODO_NOT_FOUND();
		return todo;
	});

export const routes = { todos: { get: getTodo } };

export default createApp(routes);
```

### Bun

The app also has a `routes` property in the format of Bun's `routes` server
option, so Bun's native router routes the requests. Pass the app to
`Bun.serve()` to set other server options, and spread `app.routes` to add your
own routes next to it:

```ts server.ts
const app = createApp(routes);

Bun.serve({
	...app,
	port: 8080,
	routes: { ...app.routes, "/health": new Response("ok") },
});
```

## App Options

`createApp` takes the [compile options](#compile-options) and these:

```ts
type CreateAppOptions = {
	mountPath?: AbsolutePath;
	context?:
		| Record<string, unknown>
		| ((
				request: Request,
				...args: TArgs
		  ) => Record<string, unknown> | Promise<Record<string, unknown>>);
	notFound?: (
		request: Request,
	) => Promise<Response> | Response | Promise<void> | void;
};
```

- `mountPath`: the path the routes are served under, such as `/internal`.
  Route paths do not include it. A path that clients use, such as `/api/v1`,
  belongs in the routes instead, declared with
  [`.prefix()`](/docs/route-builder#path-prefixes), so that clients and OpenAPI
  documents include it.
- `context`: values to seed the request [context](/docs/context) with before
  middleware runs, or a function, sync or async, that returns them for each
  request. They are not type-checked against the context types routes declare.
  If the function throws, the response is an `INTERNAL_SERVER_ERROR`.

  ```ts
  createApp(routes, {
  	context: async (request) => ({ user: await authenticate(request) }),
  });
  ```

  The function also receives what the runtime passes to `fetch` after the
  request, such as the `env` bindings of Cloudflare Workers or the connection
  info of Deno. Their types are inferred from the function's parameters:

  ```ts
  export default createApp(routes, {
  	context: (request, env: Env) => ({ db: env.DB }),
  }) satisfies ExportedHandler<Env>;
  ```

- `notFound`: the response for requests that match no route. Return nothing to
  keep the default response, the
  [`NOT_FOUND`](/docs/http-behavior/errors#built-in-errors) error, and only run
  side effects.

Errors a route does not send as an error response, such as errors thrown by
handlers, are sent as
[`INTERNAL_SERVER_ERROR`](/docs/http-behavior/errors#built-in-errors) responses
and passed to [`onError`](#error-handling).

## Compile Options

```ts
type CompileRoutesOptions = {
	bodyCodecs?: readonly BodyCodec[];
	disableRequestValidation?: boolean;
	disableResponseValidation?: boolean;
	onError?: (error: RouteError, request: Request) => void;
};
```

- `bodyCodecs`: see [Request and Response Bodies](#request-and-response-bodies).
- `disableRequestValidation`, `disableResponseValidation`: see
  [Disabling Server Validation](/docs/http-behavior/schemas#disabling-server-validation).
- `onError`: see [Error Handling](#error-handling).

The same options are taken by `compileRoutes` when
[integrating with a framework](/docs/server/framework-integration#compiling-routes).

## Paths

Path params are written as `:name` or `{name}`. Matching follows
[rou3](https://github.com/h3js/rou3): static segments take precedence over
params, and one trailing slash is ignored. Param values are percent-decoded.

## Request and Response Bodies

Request bodies are decoded with custom `bodyCodecs` first and the
[default codecs](/docs/http-behavior/serialization#default-codecs) after them.
A codec's `deserialize` receives the Fetch `Request`.

Handlers can return any value supported by the default codecs. A custom
serializer must return a Fetch `Response` body, such as a string, `Blob`,
`FormData`, byte array, or `ReadableStream`, or an async iterable of byte
chunks. To send it with its own headers, return it wrapped in
[`serializedBody()`](/docs/http-behavior/serialization#serializer-result).

## Error Handling

[Declared and built-in errors](/docs/http-behavior/errors) are sent as JSON
error responses. `onError` observes each of them, and `RouteError`s that end a
stream after its response started, such as stream item validation failures. It
is not awaited, and errors it throws or rejects with are ignored, so it cannot
change the response:

```ts
export default createApp(routes, {
	onError: (error, request) => {
		if (error.status >= 500) console.error(request.url, error, error.cause);
	},
});
```

A response validation failure is sent as an `INTERNAL_SERVER_ERROR` whose
`cause` holds the validation `location` and `issues`. With `createApp`,
`onError` also receives the `INTERNAL_SERVER_ERROR` created for other thrown
errors, whose `cause` is the thrown error.
