---
title: Fetch Runtime
description: Serve rest-rpc routes with Fetch Request and Response
---

The Fetch runtime turns a Fetch `Request` into a `Response`. Use it with
fetch-native runtimes such as Bun, Deno, and Cloudflare Workers, or with
frameworks built on Fetch such as Hono.

## Install

```package-install
npm i @rest-rpc/server
```

## Usage

Compile the route tree, then either let rest-rpc route requests with the
catch-all handler, or register each compiled route on a router you already
have.

```ts
import { compileRoutes, createCatchAllHandler, route } from "@rest-rpc/server";
import { z } from "zod";

const todos = new Map([["todo_1", { id: "todo_1", title: "Write docs" }]]);

const getTodo = route
	.get("/todos/:id")
	.params(z.object({ id: z.string() }))
	.handler(({ params }) => {
		const todo = todos.get(params.id);
		return todo
			? { status: 200, body: todo }
			: { status: 404, body: { code: "TODO_NOT_FOUND" as const } };
	});

export const routes = { todos: { get: getTodo } };

const handler = createCatchAllHandler(
	compileRoutes(routes, { prefix: "/api" }),
);

export default {
	async fetch(request: Request) {
		const result = await handler(request);
		return result.matched
			? result.response
			: new Response("Not found", { status: 404 });
	},
};
```

The catch-all handler resolves to `{ matched: true, response }` when the request
matches a route, and `{ matched: false }` otherwise, so the surrounding runtime
can provide fallback routing.

## Registering Routes on a Router

`compileRoutes` returns one route per method and path:

```ts
type FetchRoute = {
	method: HttpMethod;
	path: string;
	handle: (request: Request, options?: HandleOptions) => Promise<Response>;
};
```

`path` has the `prefix` applied. `handle` runs validation, middleware, and the
handler for a request that is already routed to it, and reads params from the
request URL. With Bun's built-in router:

```ts
const bunRoutes: Record<
	string,
	Record<string, (request: Request) => Promise<Response>>
> = {};
for (const route of compileRoutes(routes, {
	prefix: "/api",
	paramSyntax: "colon",
})) {
	(bunRoutes[route.path] ??= {})[route.method] = (request) =>
		route.handle(request);
}

Bun.serve({
	routes: bunRoutes,
	fetch: () => new Response("Not found", { status: 404 }),
});
```

See [Frameworks](/docs/server/frameworks) for more examples.

## Options

```ts
type CompileRoutesOptions = {
	bodyCodecs?: readonly BodyCodec[];
	disableRequestValidation?: boolean;
	disableResponseValidation?: boolean;
	paramSyntax?: "colon" | "braces";
	prefix?: `/${string}`;
	requestValidationErrorHandler?: RequestValidationErrorHandler;
	responseValidationErrorHandler?: ResponseValidationErrorHandler;
};
```

- `prefix`: path prefix prepended to every route path.
- `paramSyntax`: rewrites path params in compiled paths to `:name` (`"colon"`)
  or `{name}` (`"braces"`) for routers that expect one of them. Paths keep the
  markers they were declared with by default.
- `bodyCodecs`: see [Request and Response Bodies](#request-and-response-bodies).
- `disableRequestValidation`, `disableResponseValidation`: see
  [Disabling Server Validation](/docs/http-behavior/schemas#disabling-server-validation).
- `requestValidationErrorHandler`, `responseValidationErrorHandler`: see [Error Handling](#error-handling).

## Handle Options

Compiled routes and the catch-all handler take per-request options:

```ts
type HandleOptions = {
	context?: Record<string, unknown>;
	params?: Record<string, string>;
	body?: unknown;
};

const response = await route.handle(request, { context: { user } });
```

- `context`: values from the host to seed the request [context](/docs/context)
  with before middleware runs, such as an authenticated user or the native
  request. They are not type-checked against the context types routes declare.
- `params`: percent-decoded path params already parsed by the framework's
  router. Passing them gives a small performance gain, as the params are not
  parsed from the request URL again.
- `body`: a request body already parsed by the framework, such as with a body
  parser. The request body is then not read, but the value is still validated
  against the route's body schema.

## Paths

Path params are written as `:name` or `{name}`. Matching follows
[rou3](https://github.com/h3js/rou3): static segments take precedence over
params, and one trailing slash is ignored. Param values are percent-decoded.

## Request and Response Bodies

Request bodies are decoded with custom `bodyCodecs` first and the
[default codecs](/docs/http-behavior/serialization#default-codecs) after them.
A codec's `deserialize` receives the Fetch `Request`.

Handlers can return any value supported by the default codecs. A custom
serializer must return a Fetch `Response` body, such as a string, `Blob`,
`FormData`, byte array, or `ReadableStream`, or an async iterable of byte
chunks. To send it with its own headers, return it wrapped in
[`serializedBody()`](/docs/http-behavior/serialization#serializer-result).

## Error Handling

Use `requestValidationErrorHandler` and `responseValidationErrorHandler` to
replace the [default validation error responses](/docs/http-behavior/errors).
Other errors reject the handler promise.

```ts
const handler = createCatchAllHandler(
	compileRoutes(routes, {
		requestValidationErrorHandler: (error, request) => {
			return Response.json(
				{ code: "VALIDATION_ERROR", issues: error.issues },
				{ status: 422 },
			);
		},
		responseValidationErrorHandler: (_error, request) => {
			return Response.json({ code: "INVALID_RESPONSE" }, { status: 500 });
		},
	}),
);

export default {
	async fetch(request: Request) {
		try {
			const result = await handler(request);
			return result.matched
				? result.response
				: new Response("Not found", { status: 404 });
		} catch (error) {
			return Response.json({ code: "INTERNAL_SERVER_ERROR" }, { status: 500 });
		}
	},
};
```
