---
title: Node HTTP
description: Serve rest-rpc routes with Node.js IncomingMessage and ServerResponse
---

The Node runtime adapts the [Fetch runtime](/docs/server/fetch) to work with Node's
`IncomingMessage` and `ServerResponse`. Each request is converted to a Fetch
`Request`, handled by the same pipeline, and the resulting Fetch `Response`,
including streams, is written back to the `ServerResponse`. Use it with
`node:http` or with frameworks that expose the native request and response,
such as Express and Fastify.

Import `compileRoutes` and `createCatchAllHandler` from `@rest-rpc/server/node` instead.
They take the same [options](/docs/server/fetch#options) as their Fetch counterparts.
The handlers they return take `req, res` instead of a `Request` and write the
response to `res` instead of returning it.

## Install

```package-install
npm i @rest-rpc/server
```

## Usage

```ts
import { createServer } from "node:http";
import { compileRoutes, createCatchAllHandler } from "@rest-rpc/server/node";
import { routes } from "./routes";

const handler = createCatchAllHandler(
	compileRoutes(routes, { prefix: "/api" }),
);

createServer(async (req, res) => {
	try {
		const { matched } = await handler(req, res);
		if (!matched) res.writeHead(404).end("Not found");
	} catch (error) {
		console.error(error);
		res.writeHead(500).end("Internal server error");
	}
}).listen(3000);
```

## Registering Routes on a Router

To register routes on a router instead, call each compiled route's `handle`:

```ts
for (const route of compileRoutes(routes, { prefix: "/api" })) {
	router.on(route.method, route.path, (req, res) => route.handle(req, res));
}
```

Params a router sets as `req.params`, as Express does, are used instead of
reading them from the request URL again.

See [Frameworks](/docs/server/frameworks) for more examples.
