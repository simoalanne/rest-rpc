`@rest-rpc/server/node` serves routes with Node's `IncomingMessage` and
`ServerResponse`, reading and writing them directly. See
[Serving Routes](/docs/server/overview) for what is shared with
[Fetch](/docs/server/fetch), and [Framework Integration](/docs/server/framework-integration)
to add the routes to a framework such as Express or Fastify.

## Usage

`createApp` from `@rest-rpc/server/node` returns a request listener. Pass it
to `http.createServer()`, which starts, configures and closes the server as
usual:

```ts server.ts
import { createServer } from "node:http";
import { createApp } from "@rest-rpc/server/node";
import { routes } from "./routes";

const server = createServer(createApp(routes)).listen(3000, () =>
	console.log("Listening on port 3000"),
);

process.on("SIGTERM", () => server.close());
```

The listener also works with `https.createServer()`.

## App Options

`createApp` takes the [route options](/docs/server/overview#route-options) and
these:

```ts
type CreateNodeAppOptions = {
	mountPath?: AbsolutePath;
	// Required when the routes declare initial context.
	context?:
		TContext | ((request: IncomingMessage) => TContext | Promise<TContext>);
	notFound?: (
		request: IncomingMessage,
		response: ServerResponse,
	) => void | Promise<void>;
};
```

- `mountPath`: the path the routes are served under, such as `/api`. See
  [Mount Path](/docs/server/overview#mount-path).
- `context`: the [initial context](/docs/middleware#values-from-the-host) the
  routes declare, or a function, sync or async, that returns it for each
  request. It is required when the routes declare initial context. If the
  function throws, the response is an `INTERNAL_SERVER_ERROR`.

  ```ts
  createApp(routes, {
  	context: async (request) => ({
  		user: await authenticate(request.headers.authorization),
  	}),
  });
  ```

- `notFound`: writes the response for requests that match no route. When it
  writes nothing, the default response, the
  [`NOT_FOUND`](/docs/http-behavior/errors#built-in-errors) error, is sent.

  ```ts
  createApp(routes, {
  	notFound: (request, response) => {
  		response.statusCode = 404;
  		response.end("Not found");
  	},
  });
  ```

Errors a route does not send as an error response, such as errors thrown by
handlers, are sent as
[`INTERNAL_SERVER_ERROR`](/docs/http-behavior/errors#built-in-errors) responses
and passed to [`onError`](/docs/server/overview#error-handling), which receives
the `IncomingMessage` as its request.
