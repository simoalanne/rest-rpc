`@rest-rpc/server/node` serves routes with Node's `IncomingMessage` and
`ServerResponse`, reading and writing them directly.

## Usage

`createApp` from `@rest-rpc/server/node` returns a request listener. Pass it
to `http.createServer()`, which starts, configures and closes the server as
usual:

```ts server.ts
import { createServer } from "node:http";
import { createApp } from "@rest-rpc/server/node";
import { routes } from "./routes";

const server = createServer(createApp(routes)).listen(3000, () =>
	console.log("Listening on port 3000"),
);

process.on("SIGTERM", () => server.close());
```

The listener also works with `https.createServer()`.

## App Options

`createApp` takes the [route options](/docs/server/overview#route-options) and
these:

```ts
type CreateNodeAppOptions = {
	/**
	 * The path the routes are served under, such as `/api`. Route paths do not
	 * include it.
	 */
	mountPath?: AbsolutePath;
	/**
	 * The initial context the routes require for each request, or a function
	 * that returns it for the request. Required when the routes require initial
	 * context. If the function throws, the response is an
	 * `INTERNAL_SERVER_ERROR`.
	 */
	context?:
		TContext | ((request: IncomingMessage) => TContext | Promise<TContext>);
	/**
	 * Functions around everything the app does for a request, the first
	 * outermost. They run before routing.
	 */
	interceptors?: readonly NodeInterceptor[];
};
```

Thrown errors are sent as [error responses](/docs/http-behavior/errors), and
requests that match no route as `NOT_FOUND`. When a response already started,
such as a stream that fails, the connection is closed instead.

`createApp` reads request bodies whole, with no size limit, so put one in
front of it, such as in a proxy.

## Interceptors

[Interceptors](/docs/server/interceptors) work as on Fetch, with `interceptor`,
`onError` and `writeErrorResponse` from `@rest-rpc/server/node`, but they
write to the `ServerResponse` instead of returning a `Response`:

```ts
import { createApp, interceptor } from "@rest-rpc/server/node";

const requestId = interceptor(({ response, next }) => {
	response.setHeader("x-request-id", crypto.randomUUID());
	return next();
});

createServer(createApp(routes, { interceptors: [requestId] }));
```

- Headers set before `next()` are sent with every response, error responses
  included, without catching errors.
- `next()` resolves once the response is written, and also rejects when a
  stream fails after it started.
- A response can't change after it's written. An interceptor that sends its
  own response writes it and doesn't call `next()`.
- `writeErrorResponse(response, error)` is the Node `errorResponse`. Check
  `response.headersSent` first, since a started response can't become an
  error response:

```ts
const sendErrors = interceptor(({ response, next }) =>
	next().catch((error) => {
		if (response.headersSent) throw error;
		return writeErrorResponse(response, error);
	}),
);
```
