`@rest-rpc/server/node` serves routes with Node's `IncomingMessage` and
`ServerResponse`, reading and writing them directly. See
[Serving Routes](/docs/server/overview) for what is shared with
[Fetch](/docs/server/fetch), and [Framework Integration](/docs/server/framework-integration)
to add the routes to a framework such as Express or Fastify.

## Usage

`createApp` from `@rest-rpc/server/node` returns a request listener. Pass it
to `http.createServer()`, which starts, configures and closes the server as
usual:

```ts server.ts
import { createServer } from "node:http";
import { createApp } from "@rest-rpc/server/node";
import { routes } from "./routes";

const server = createServer(createApp(routes)).listen(3000, () =>
	console.log("Listening on port 3000"),
);

process.on("SIGTERM", () => server.close());
```

The listener also works with `https.createServer()`.

## App Options

`createApp` takes the [route options](/docs/server/overview#route-options) and
these:

```ts
type CreateNodeAppOptions = {
	mountPath?: AbsolutePath;
	// Required when the routes declare initial context.
	context?:
		TContext | ((request: IncomingMessage) => TContext | Promise<TContext>);
	interceptors?: readonly NodeInterceptor[];
};
```

- `mountPath`: the path the routes are served under, such as `/api`. See
  [Mount Path](/docs/server/overview#mount-path).
- `context`: the [initial context](/docs/middleware#values-from-the-host) the
  routes declare, or a function, sync or async, that returns it for each
  request. It is required when the routes declare initial context. If the
  function throws, the response is an `INTERNAL_SERVER_ERROR`.

  ```ts
  createApp(routes, {
  	context: async (request) => ({
  		user: await authenticate(request.headers.authorization),
  	}),
  });
  ```

- `interceptors`: functions around everything the app does for a request. See
  [Interceptors](#interceptors).

Errors a route does not send as an error response, such as errors thrown by
handlers, are sent as
[`INTERNAL_SERVER_ERROR`](/docs/http-behavior/errors#built-in-errors) responses,
and requests that match no route as
[`NOT_FOUND`](/docs/http-behavior/errors#built-in-errors) errors.

## Interceptors

An interceptor wraps everything the app does for a request, for work that
has to happen before routing or on every response, such as API key checks,
request IDs, logging, or CORS. Create one with `interceptor()` from
`@rest-rpc/server/node`, which types the function and returns it unchanged:

```ts
import { createApp, interceptor } from "@rest-rpc/server/node";

const apiKey = interceptor(({ request, response, next }) => {
	if (request.headers["x-api-key"] === API_KEY) return next();
	response.writeHead(403).end("Forbidden");
});

const cors = interceptor(({ request, response, next }) => {
	response.setHeader("access-control-allow-origin", "https://app.example.com");
	response.setHeader("vary", "Origin");
	if (request.method !== "OPTIONS") return next();
	response.setHeader(
		"access-control-allow-methods",
		"GET, POST, PUT, PATCH, DELETE",
	);
	response.setHeader(
		"access-control-allow-headers",
		"content-type, authorization",
	);
	response.writeHead(204).end();
});

createServer(createApp(routes, { interceptors: [cors, apiKey] }));
```

- Interceptors run in order, the first outermost, and the app's own handling
  is innermost.
- They receive every request, including ones that match no route and
  `OPTIONS` preflights, except those a
  [static route](/docs/route-builder#static-responses) serves. Static routes
  are for public content, so complete a route with `.handler()` when it needs
  access control, and put headers such as CORS in the static response itself.
- `route` is the matched route's definition, with its path and
  [`meta`](/docs/middleware#metadata), or `undefined` when no route matches.
- The app writes to `response`, so headers set before `next()` are sent with
  every response, error responses included. An interceptor that writes its
  own response doesn't call `next()`.
- `next()` resolves once the response is written, streams included, error
  responses too, and rejects only for bugs. See
  [What `next()` Returns](#what-next-returns).
- An error that reaches the app, from `next()` or thrown by an interceptor,
  is sent as an
  [`INTERNAL_SERVER_ERROR`](/docs/http-behavior/errors#built-in-errors)
  response, or closes the connection when the response already started. An
  interceptor that finishes without a response gets the same
  `INTERNAL_SERVER_ERROR`.

Unlike [Fetch interceptors](/docs/server/fetch#interceptors), a Node
interceptor can't change a response after it is written, such as to rewrite
an error body. It can change `request` before `next()`, but routing isn't
repeated, so changing its URL or method isn't supported. Per-route logic with
typed context belongs in [middleware](/docs/middleware).

### What `next()` Returns

| What happens in the app                                                                                                                             | `next()`                                                      |
| --------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------- |
| The route's response is written                                                                                                                     | Resolves                                                      |
| A `RouteError` is thrown: a [defined or built-in error](/docs/http-behavior/errors), such as a request validation failure or a handler's `NotFound` | Resolves, once its JSON error response is written             |
| No route matches, so `route` is `undefined`                                                                                                         | Resolves, once the `NOT_FOUND` JSON error response is written |
| Anything else is thrown, such as an `Error` from a handler, middleware, the `context` function or a codec                                           | Rejects with the thrown value, unchanged                      |
| A stream fails after the response started                                                                                                           | Rejects with the stream's error                               |

Every outcome the contract describes, including errors, is a written response
whose status is in `response.statusCode`. A rejection only ever means a bug.
When nothing catches it, the app sends an `INTERNAL_SERVER_ERROR` response,
or closes the connection when the response already started.

So error reporting is a `try`/`catch` around `next()`:

```ts
const logErrors = interceptor(async ({ request, next }) => {
	try {
		await next();
	} catch (error) {
		// The thrown value as is, such as an `Error` with its stack and `cause`.
		console.error(request.method, request.url, error);
		throw error; // The app sends INTERNAL_SERVER_ERROR.
	}
});
```

### Error Responses

`writeErrorResponse(response, error)` writes the response the app sends for a
`RouteError`: its status and headers, and a JSON `{ code, message, data? }`
body. The [client](/docs/client/fetch-client) decodes that response as a
`RouteError`, so an error an interceptor sends is handled like any other. No
route definition applies, so the error is sent with its own status, `data`
and headers, without validation:

```ts
import { routeError } from "@rest-rpc/server";
import { interceptor, writeErrorResponse } from "@rest-rpc/server/node";

const RateLimited = routeError("RATE_LIMITED", { status: 429 });

const rateLimit = interceptor(({ request, response, next }) =>
	limiter.allow(request)
		? next()
		: writeErrorResponse(response, new RateLimited()),
);
// The client rejects with a RouteError whose code is "RATE_LIMITED".
```

### Not Found

The app matches the route before the interceptors run. When no route
matches, `route` is `undefined`, and calling `next()` would write the app's
`NOT_FOUND` error response. An interceptor that writes its own response
instead doesn't call `next()`:

```ts
const notFound = interceptor(({ response, route, next }) => {
	if (route) return next();
	response.writeHead(404).end("Not found");
});
```
