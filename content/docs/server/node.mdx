The Node runtime serves the same app as the [Fetch runtime](/docs/server/fetch)
on `node:http`. Apps are created with `createApp` and configured with the same
[options](/docs/server/fetch#app-options), and routes behave the same, including
streamed responses. This page covers `serve`, which starts the server. To add
the routes to an existing framework such as Express or Fastify, see
[Framework Integration](/docs/server/framework-integration).

## Install

```package-install
npm i @rest-rpc/server
```

## Serve

`serve` starts a `node:http` server for an app:

```ts server.ts
import { createApp } from "@rest-rpc/server";
import { serve } from "@rest-rpc/server/node";
import { routes } from "./routes";

const server = serve(createApp(routes), {
	port: 3000,
	onListen: (address) => console.log(`Listening on port ${address.port}`),
});

process.on("SIGTERM", () => server.close());
```

```ts
type ServeOptions = {
	port?: number;
	hostname?: string;
	onListen?: (address: AddressInfo) => void;
};
```

- `port`: defaults to `3000`. With `0`, a free port is chosen and passed to
  `onListen`.
- `hostname`: listens on all interfaces when omitted, as `server.listen()` does.
- `onListen`: called once the server listens, with the address it listens on.

`serve` returns the underlying `http.Server`, so closing it and handling its
events are up to you.
