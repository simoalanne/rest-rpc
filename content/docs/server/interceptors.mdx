---
title: Interceptors
description: Run code around everything the server does for a request, and handle its errors.
---

An interceptor is a function around everything the server does for a
request, routing included, for work such as API keys, logging, CORS or error
reporting. It's the standard middleware pattern: work before `next()`, call
`next()` for the rest, work after it. Per-route logic with typed context
belongs in [middleware](/docs/middleware) instead.

## The Lifecycle

Run this to see where each part runs, including for failures:

```ts server.ts
import {
	createApp,
	errorResponse,
	interceptor,
	onError,
	route,
} from "@rest-rpc/server";
import { z } from "zod";

const timing = interceptor(async ({ next }) => {
	console.log("timing: before next");
	try {
		const response = await next();
		console.log(`timing: after next, ${response.status}`);
		return response;
	} catch (error) {
		console.log("timing: next rejected"); // never: sendErrors catches first
		throw error;
	}
});

// Turns errors into responses for the interceptors before it.
const sendErrors = interceptor(({ next }) => next().catch(errorResponse));

const report = onError((error) =>
	console.log(`onError: ${(error as Error).message}`),
);

const getTodo = route
	.$context<{ user: string }>()
	.get("/todos/:id")
	.params(z.object({ id: z.string().regex(/^\d+$|^fail$/) }))
	.use(async ({ next }) => {
		console.log("middleware: before next");
		try {
			return await next();
		} finally {
			console.log("middleware: after next");
		}
	})
	.handler(({ params, context }) => {
		console.log(`handler: ${params.id} for ${context.user}`);
		if (params.id === "fail") throw new Error("handler failed");
		return { id: params.id };
	});

const app = createApp(
	{ getTodo },
	{
		context: () => {
			console.log("context");
			return { user: "ada" };
		},
		interceptors: [timing, sendErrors, report],
	},
);

for (const path of ["/todos/1", "/todos/abc", "/todos/fail", "/missing"]) {
	console.log(path);
	await app.fetch(new Request(`http://localhost${path}`));
}
```

```txt
/todos/1
  timing: before next
  context
  middleware: before next
  handler: 1 for ada
  middleware: after next
  timing: after next, 200
/todos/abc                    (request validation fails: no middleware, no handler)
  timing: before next
  context
  onError: Request validation failed.
  timing: after next, 400
/todos/fail
  timing: before next
  context
  middleware: before next
  handler: fail for ada
  middleware: after next
  onError: handler failed
  timing: after next, 500
/missing                      (no route: no context)
  timing: before next
  onError: Not found.
  timing: after next, 404
```

- Interceptors run in order, the first outermost, before routing and before
  the `context` function.
- Request validation runs after `context` and before middleware.
- An error rejects `next()` back through every interceptor, until one catches
  it. Without `sendErrors`, `timing` would log "next rejected", and the app
  would send the error after the last interceptor.

## Writing Interceptors

<Tabs>
<Tab title="Fetch">

```ts
import { createApp, interceptor, routeError } from "@rest-rpc/server";

const Forbidden = routeError("FORBIDDEN", { status: 403 });

const apiKey = interceptor(({ request, route, next }) => {
	if (route?.meta?.access === "public") return next();
	if (request.headers.get("x-api-key") !== API_KEY) throw new Forbidden();
	return next();
});

export default createApp(routes, { interceptors: [apiKey] });
```

</Tab>
<Tab title="Node">

```ts
import { routeError } from "@rest-rpc/server";
import { createApp, interceptor } from "@rest-rpc/server/node";

const Forbidden = routeError("FORBIDDEN", { status: 403 });

const apiKey = interceptor(({ request, route, next }) => {
	if (route?.meta?.access === "public") return next();
	if (request.headers["x-api-key"] !== API_KEY) throw new Forbidden();
	return next();
});

createServer(createApp(routes, { interceptors: [apiKey] }));
```

</Tab>
</Tabs>

- **`route`** is the matched route's definition, with its path and
  [`meta`](/docs/middleware#metadata), or `undefined` when nothing matches.
- **Every request** runs them, `OPTIONS` and unmatched ones included, except
  [static routes](/docs/route-builder#static-responses), whose response is
  prebuilt. Give a route `.handler()` when it needs access control.
- **Errors are thrown.** A `RouteError` is sent with its own status, like
  `Forbidden` above.
- **On Fetch,** `next()` resolves with the `Response`, and `next(request)`
  continues with another request, such as one with other headers. Routing
  isn't repeated, so its URL and method must stay the same. `args` are the
  untyped arguments the runtime passed to `fetch` after the request, such as
  the `env` of Cloudflare Workers: `const [env] = args as [Env]`.
- **On Node,** `next()` resolves once the response is written, streams
  included. Headers set on `response` before `next()` are sent with every
  response, error responses included, and an interceptor that writes its own
  response doesn't call `next()`.

## What `next()` Returns

| What happens                                                                                              | `next()`                                                               |
| --------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------- |
| The route responds                                                                                        | Resolves: with the `Response` on Fetch, once it's written on Node      |
| A `RouteError` is thrown, such as a request validation failure or a handler's `errors.TODO_NOT_FOUND()`   | Rejects with it, with the status, `data` and headers it's sent with    |
| A response fails validation                                                                               | Rejects with an `INTERNAL_SERVER_ERROR` whose `cause` holds the issues |
| No route matches                                                                                          | Rejects with a `NOT_FOUND` error                                       |
| Anything else is thrown, such as an `Error` from a handler, middleware, the `context` function or a codec | Rejects with it, unchanged                                             |
| A stream fails after the response started                                                                 | Rejects on Node. On Fetch, `next()` already resolved: see `onError`    |

A rejected route error keeps its class, message and `cause`, so
`error instanceof TodoNotFound` works, and its `data` is the validated value the
client receives.

## Reporting Errors

`onError(callback)` creates an interceptor that calls `callback` with every
error thrown after it, then rethrows it:

```ts
import { onError } from "@rest-rpc/server"; // or "@rest-rpc/server/node"

const report = onError((error, { request, route }) => {
	logger.error({ method: request.method, path: route?.path, error });
});
```

It reports stream failures too. On Fetch, a body that fails while it streams
fails after `next()` resolved, so `onError` wraps each response body to report
it, at about 1.6 µs per response. A client that cancels a body isn't reported.

Place it after interceptors that turn errors into responses, since those it
follows never see the errors.

## Sending Errors

What no interceptor catches, the app sends with `errorResponse(error)` on
Fetch and `writeErrorResponse(response, error)` on Node: a `RouteError` with
its status, headers and a JSON `{ code, message, data? }` body, and anything
else as an `INTERNAL_SERVER_ERROR` with the value as `cause`. Clients decode
both as a `RouteError`.

An interceptor that catches with the same function sends errors earlier, so
the interceptors before it receive error responses as responses:

<Tabs>
<Tab title="Fetch">

```ts
const sendErrors = interceptor(({ next }) => next().catch(errorResponse));

createApp(routes, { interceptors: [cors, sendErrors, report, apiKey] });
```

</Tab>
<Tab title="Node">

```ts
import { interceptor, writeErrorResponse } from "@rest-rpc/server/node";

const sendErrors = interceptor(({ response, next }) =>
	next().catch((error) => {
		if (response.headersSent) throw error; // the app closes the connection
		return writeErrorResponse(response, error);
	}),
);
```

</Tab>
</Tabs>

An error an interceptor throws isn't checked against the route. To send a
code the route [defines](/docs/http-behavior/errors#defined-and-undefined-errors),
throw the route's own error class.

## Not Found

When no route matches, `route` is `undefined`, and `next()` rejects with
`NOT_FOUND`. To send something else, don't call `next()`:

```ts
const notFound = interceptor(({ route, next }) =>
	route ? next() : new Response("Not found", { status: 404 }),
);
```

## CORS

CORS headers have to be on every response, error responses included, and
preflights are answered before routing:

<Tabs>
<Tab title="Fetch">

```ts
const corsHeaders = {
	"access-control-allow-origin": "https://app.example.com",
	vary: "Origin",
};

const cors = interceptor(async ({ request, next }) => {
	if (request.method === "OPTIONS") {
		return new Response(null, {
			status: 204,
			headers: {
				...corsHeaders,
				"access-control-allow-methods": "GET, POST, PUT, PATCH, DELETE",
				"access-control-allow-headers": "content-type, authorization",
			},
		});
	}
	const response = await next();
	// A returned `Response` may have immutable headers, so it's copied.
	const copy = new Response(response.body, response);
	for (const [name, value] of Object.entries(corsHeaders)) {
		copy.headers.set(name, value);
	}
	return copy;
});

// sendErrors after cors, so error responses get the headers too.
createApp(routes, { interceptors: [cors, sendErrors] });
```

</Tab>
<Tab title="Node">

```ts
// Headers set before next() are on error responses too, so no catch is needed.
const cors = interceptor(({ request, response, next }) => {
	response.setHeader("access-control-allow-origin", "https://app.example.com");
	response.setHeader("vary", "Origin");
	if (request.method !== "OPTIONS") return next();
	response.setHeader(
		"access-control-allow-methods",
		"GET, POST, PUT, PATCH, DELETE",
	);
	response.setHeader(
		"access-control-allow-headers",
		"content-type, authorization",
	);
	response.writeHead(204).end();
});
```

</Tab>
</Tabs>

## In Frameworks

[`createRouteHandlers` and `createCatchAllHandler`](/docs/server/framework-integration)
take `interceptors` too. They run around each route's `handle`, after the
framework routed the request, so `route` is always defined, and the catch-all
handler runs them only for matched requests. Framework middleware only sees
error responses, so report errors with their `cause` here:

```ts
const handlers = createRouteHandlers(routes, {
	interceptors: [onError((error) => logger.error(error))],
});
```

Route errors no interceptor catches are sent as error responses, and other
errors reject `handle` for the framework's error handling.
