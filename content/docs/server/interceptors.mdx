---
title: Interceptors
description: Run code around every request the app serves.
---

An interceptor is a function around everything the app does for a request. It
receives the request and the matched route, calls `next()` for the rest, and
returns the response. Interceptors are for app-wide work that rest-rpc leaves
to the app, such as API keys, CORS, rate limits or logging. Per-route logic
with typed context belongs in [middleware](/docs/middleware). Served from a
[framework](/docs/server/framework-integration), the framework's own
middleware often does the same job.

The [client](/docs/client/fetch-client#interceptors) has interceptors with the
same shape around each HTTP exchange.

## Write an Interceptor

`interceptor()` types the function and returns it unchanged. Pass interceptors
to `createApp` in `interceptors`:

```ts
import { createApp, interceptor } from "@rest-rpc/server";

const logging = interceptor(async ({ request, route, next }) => {
	const response = await next();
	console.log(request.method, route?.path, response.status);
	return response;
});

export default createApp(router, { interceptors: [logging] });
```

```ts
type Interceptor = (args: {
	request: Request;
	/**
	 * The matched route's definition, with its `path` and `meta`, or
	 * `undefined` when no route matches the request.
	 */
	route: InterceptedRoute | undefined;
	/**
	 * What the runtime passed to `fetch` after the request, such as the `env`
	 * of Cloudflare Workers. Untyped, so narrow them where they are read:
	 * `const [env] = args as [Env]`.
	 */
	args: readonly unknown[];
	/**
	 * Handles the request with the later interceptors and the route. Pass
	 * another request to continue with it, such as one with other headers.
	 * Routing is not repeated, so keep its URL and method.
	 */
	next: (request?: Request) => Promise<Response>;
}) => Response | Promise<Response>;
```

An interceptor that returns a `Response` without calling `next()` answers the
request itself, and one that throws sends an error.

## Order

The app matches the route first, then runs the interceptors in order, the
first outermost. The last one's `next()` runs the route: the
[context](/docs/middleware#values-from-the-host) function, request validation,
middleware and the handler. `next()` resolves when the response starts, before
its body streams.

Interceptors run for every request, including ones that match no route, except
for [static routes](/docs/route-builder#static-responses), which are sent as
they are.

## Errors

`next()` resolves with the responses the route sends, and rejects with every
error thrown after the interceptor:

- A `RouteError` rejects as it's sent, with its status, `data` and headers.
  This includes request validation failures, `NOT_FOUND` when no route
  matches, and the route's own errors, which keep their class.
- A response that fails validation rejects with an `INTERNAL_SERVER_ERROR`
  whose `cause` has the issues.
- Anything else rejects unchanged.

An interceptor sends an error by throwing it, and a `RouteError` is sent with
its own status. It isn't checked against the route, so to send a code the
route [defines](/docs/http-behavior/errors#defined-and-undefined-errors),
throw the route's own error class.

## Sending Errors

What no interceptor catches, the app sends with `errorResponse(error)`: a
`RouteError` as a JSON `{ code, message, data? }` response with its status,
and anything else as an `INTERNAL_SERVER_ERROR`. An interceptor that catches
with it sends errors earlier, so the interceptors before it receive error
responses instead of rejections:

```ts
import { createApp, errorResponse, interceptor } from "@rest-rpc/server";

createApp(router, {
	interceptors: [
		cors, // receives error responses too
		interceptor(({ next }) => next().catch(errorResponse)),
		apiKey,
	],
});
```

## Reporting Errors

`onError(callback)` creates an interceptor that calls `callback` with every
error thrown after it, and then rethrows it. That includes a
[Server-Sent Events](/docs/server-sent-events) stream that fails after the
response started. Place it after interceptors that turn errors into responses:

```ts
import { onError } from "@rest-rpc/server";

const report = onError((error, { request, route }) => {
	logger.error({ method: request.method, path: route?.path, error });
});
```

`onError` doesn't report other bodies that fail while they stream, such as a
raw `ReadableStream` or a returned `Response`. On
[Node](/docs/server/node#interceptors), it reports every body.
