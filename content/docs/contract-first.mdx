---
title: Contract-first
description: Define routes in a shared contract and implement them separately.
---

Import `route` from `@rest-rpc/core` to define a route independently
of its server implementation. The contract can be shared directly with a Fetch
client and implemented with `@rest-rpc/server`.

The definition methods are the same as the [Route Builder](/docs/route-builder).
The difference is that responses are defined with schemas rather than inferred
from handlers.

## Define Routes

```ts contract.ts
import { route } from "@rest-rpc/core";
import { z } from "zod";

const todoSchema = z.object({ id: z.string(), title: z.string() });

const create = route.body(z.object({ title: z.string() })).response(todoSchema);

const get = route
	.get("/todos/:id")
	.params(z.object({ id: z.string() }))
	.response(todoSchema)
	.error("TODO_NOT_FOUND", { status: 404 });

export const api = { todos: { create, get } };
```

Use `.response()` for each successful response, with `sse(schema)` for
streams, and `.error()` for each [error](/docs/route-builder#define-errors).
These schemas define handler and client types and provide
[runtime validation](/docs/http-behavior/schemas).
See [Server-Sent Events](/docs/streaming) for stream handlers.

## Implement Routes

Pass a contract route to `implement()` to get a server route builder for it,
then attach its handler:

```ts server.ts
import { implement } from "@rest-rpc/server";
import { api } from "./contract";
import { createTodo, findTodo } from "./todos";

const create = implement(api.todos.create).handler(({ body: { title } }) =>
	createTodo(title),
);

const get = implement(api.todos.get).handler(({ params, errors }) => {
	const todo = findTodo(params.id);
	if (!todo) throw errors.TODO_NOT_FOUND();
	return todo;
});

export const routes = { todos: { create, get } };
```

The implementation must match the contract's request segments and defined
responses, and throw the contract's defined errors. Compile and register the completed routes as usual.

## Context, Middleware and Metadata

[Context, middleware and metadata](/docs/middleware) work as for server-first
routes, with two differences.

`$context<T>()` and `.use()` are called on the `implement()` result, before
`.handler()`. Pass a contract tree to `implement()` to share them with every
route in the tree:

```ts
const todos = implement(api.todos)
	.$context<{ headers: Headers }>()
	.use(authenticate); // injects user

export const routes = {
	todos: {
		create: todos.create.handler(({ body, context }) =>
			createTodo(body.title, context.user),
		),
		get: todos.get.handler(({ params, errors }) => {
			const todo = findTodo(params.id);
			if (!todo) throw errors.TODO_NOT_FOUND();
			return todo;
		}),
	},
};
```

Metadata is part of the contract, so declare its shape with `$meta<T>()` and
set it with `.meta()` on contract routes. Middleware on the implementation
reads `route.meta` with the shape of the routes it runs on.

:::error[Reserved Keys]
Don't use `use` or `$context` as top-level keys of a contract tree passed to `implement()`. They are reserved for the implementer.
:::

## Use in a Client

Pass the shared contract directly to `createClient()`, and the client to
`createTanstackQueryUtils()` if you use TanStack Query. No [contract extraction](/docs/client/contract-extraction)
step is needed, and the client can [validate responses](/docs/client/fetch-client#response-validation)
with the contract's schemas.

See the [Contract-first Quickstart](/docs/contract-first-quickstart) for a
complete example.
