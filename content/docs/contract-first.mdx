---
title: Contract-first
description: Declare routes in a shared contract and implement them separately.
---

Import `route` from `@rest-rpc/core` to declare a route independently
of its server implementation. The contract can be shared directly with a Fetch
client and implemented with `@rest-rpc/server`.

The declaration methods are the same as the [Route Builder](/docs/route-builder).
The difference is that responses are declared with schemas rather than inferred
from handlers.

## Declare Routes

```ts contract.ts
import { route } from "@rest-rpc/core";
import { z } from "zod";

const todoSchema = z.object({ id: z.string(), title: z.string() });

const create = route.body(z.object({ title: z.string() })).response(todoSchema);

const get = route
	.get("/todos/:id")
	.params(z.object({ id: z.string() }))
	.response(todoSchema)
	.response(z.object({ code: z.literal("TODO_NOT_FOUND") }), { status: 404 });

export const api = { todos: { create, get } };
```

Use `.response()` for each response and `.streamResponse()` for streams. These
schemas define handler and client types and provide [runtime validation](/docs/http-behavior/schemas).
See [Streaming](/docs/streaming) for stream handlers.

## Implement Routes

`@rest-rpc/server/node` and `@rest-rpc/server/fetch` export `implement()`. Pass a route or route tree to get
builders with typed `.handler()` methods:

```ts server.ts
import { implement } from "@rest-rpc/server/node";
import { api } from "./contract";
import { createTodo, findTodo } from "./todos";

const implementer = implement(api);

const create = implementer.todos.create.handler(({ body: { title } }) =>
	createTodo(title),
);

const get = implementer.todos.get.handler(({ params }) => {
	const todo = findTodo(params.id);
	return todo ?? { status: 404, body: { code: "TODO_NOT_FOUND" } };
});

export const routes = { todos: { create, get } };
```

The implementation must match the contract's request segments and declared
responses. Compile and register the completed routes as usual.

## Context And Middleware

Context and middleware are supported in contract-first routes. See [Context](/docs/context) and [Middleware](/docs/middleware) for details.

`$context<T>()` and `.use()` can be called on the root builder to share context and middleware across all routes:

```ts
const implementer = implement(api)
	.$context<{ user: { id: string } }>()
	.use(yourMiddleware);
const createTodo = implementer.todos.create.handler(yourHandler);
```

Alternatively, call them on a specific route to share context and middleware only with that route:

```ts
const implementer = implement(api);
const create = implementer.todos.create
	.$context<{ user: { id: string } }>()
	.use(yourMiddleware)
	.handler(yourHandler);
```

:::error[Reserved Keys]
Don't use `use` or `$context` as top-level keys in your contract. They are reserved for the implementation builder.
:::

## Use in a Client

Pass the shared contract directly to `initClient()` or
`createTanstackQueryUtils()`. No [contract extraction](/docs/client/contract-extraction)
step is needed, and the client can [validate responses](/docs/client/fetch-client#response-validation)
with the contract's schemas.

See the [Contract-first Quickstart](/docs/contract-first-quickstart) for a
complete example.
