---
title: Contract-first
description: Declare routes in a shared contract and implement them separately.
---

Import `route` from `@rest-rpc/core` to declare a route independently
of its server implementation. The contract can be shared directly with a Fetch
client and implemented with `@rest-rpc/server`.

The declaration methods are the same as the [Route Builder](/docs/route-builder).
The difference is that responses are declared with schemas rather than inferred
from handlers.

## Declare Routes

```ts contract.ts
import { route } from "@rest-rpc/core";
import { z } from "zod";

const todoSchema = z.object({ id: z.string(), title: z.string() });

const create = route.body(z.object({ title: z.string() })).response(todoSchema);

const get = route
	.get("/todos/:id")
	.params(z.object({ id: z.string() }))
	.response(todoSchema)
	.error("TODO_NOT_FOUND", { status: 404 });

export const api = { todos: { create, get } };
```

Use `.response()` for each successful response, `.streamResponse()` for
streams, and `.error()` for each [error](/docs/route-builder#declare-errors).
These schemas define handler and client types and provide
[runtime validation](/docs/http-behavior/schemas).
See [Streaming](/docs/streaming) for stream handlers.

## Implement Routes

Pass a contract route to `implement()` to get a server route builder for it,
then attach its handler:

```ts server.ts
import { implement } from "@rest-rpc/server";
import { api } from "./contract";
import { createTodo, findTodo } from "./todos";

const create = implement(api.todos.create).handler(({ body: { title } }) =>
	createTodo(title),
);

const get = implement(api.todos.get).handler(({ params, errors }) => {
	const todo = findTodo(params.id);
	if (!todo) throw errors.TODO_NOT_FOUND();
	return todo;
});

export const routes = { todos: { create, get } };
```

The implementation must match the contract's request segments and declared
responses, and throw the contract's declared errors. Compile and register the completed routes as usual.

## Context And Middleware

Context and middleware are supported in contract-first routes. See [Context](/docs/context) and [Middleware](/docs/middleware) for details.

Call `$context<T>()` and `.use()` on an implemented route before `.handler()`:

```ts
const create = implement(api.todos.create)
	.$context<{ user: { id: string } }>()
	.use(authenticate)
	.handler(({ body, context }) => createTodo(body.title, context.get("user")));
```

### Share Across Routes

To share context and middleware with several routes, pass a contract tree to
`implement()`. The implementer mirrors the tree, and `$context<T>()` and
`.use()` on it apply to every route in the tree:

```ts
const todos = implement(api.todos)
	.$context<{ user: { id: string } }>()
	.use(authenticate);

export const routes = {
	todos: {
		create: todos.create.handler(({ body, context }) =>
			createTodo(body.title, context.get("user")),
		),
		get: todos.get.handler(({ params, errors }) => {
			const todo = findTodo(params.id);
			if (!todo) throw errors.TODO_NOT_FOUND();
			return todo;
		}),
	},
};
```

:::error[Reserved Keys]
Don't use `use` or `$context` as top-level keys of a contract tree passed to `implement()`. They are reserved for the implementer.
:::

## Use in a Client

Pass the shared contract directly to `initClient()` or
`createTanstackQueryUtils()`. No [contract extraction](/docs/client/contract-extraction)
step is needed, and the client can [validate responses](/docs/client/fetch-client#response-validation)
with the contract's schemas.

See the [Contract-first Quickstart](/docs/contract-first-quickstart) for a
complete example.
