---
title: Error Responses
description: Default server responses for invalid requests and responses, and how errors reach your framework.
---

The server rejects invalid requests before the handler runs and checks
handler output before it is sent. This page lists the default responses. The
[Fetch](/docs/server/fetch#error-handling) and
[Node HTTP](/docs/server/node#error-handling) runtime pages document how to
replace them.

## Default Responses

| Situation                                                                                  | Status | Body                            |
| ------------------------------------------------------------------------------------------ | ------ | ------------------------------- |
| Request `Content-Type` is not declared by the route                                        | `415`  | `{ message }`                   |
| Request body cannot be decoded                                                             | `400`  | `{ message }`                   |
| Request body exceeds `requestBodyLimit`                                                    | `413`  | `{ message }`                   |
| [Request validation](/docs/http-behavior/schemas#request-validation) fails                 | `400`  | `{ message, validationErrors }` |
| [Response validation](/docs/http-behavior/schemas#response-validation-on-the-server) fails | `500`  | `{ message }`                   |

The request validation body groups Standard Schema issues by location:

```ts
{
	message: string;
	validationErrors: {
		body: ValidationIssue[];
		query: ValidationIssue[];
		params: ValidationIssue[];
		headers: ValidationIssue[];
	};
}
```

The response validation body does not expose validation details.

## Validation Errors

`RequestValidationError` has:

- `status`: the default status, `400`.
- `issues`: Standard Schema issues grouped by `body`, `query`, `params`, and `headers`.
- `responseBody`: the default response body.

`ResponseValidationError` has:

- `status`: the default status, `500`.
- `location`: `"body"`, `"headers"`, or `"stream"`.
- `issues`: the Standard Schema issues.
- `responseBody`: the default response body.

A stream item that fails validation cannot change the response status. The
stream ends instead.

## Other Errors

Errors thrown by handlers, middleware, or custom serializers are not converted
into responses. They reject the handler promise, and reach the framework's
error handling when routes are registered on a framework. Returning a status that the
route does not declare also produces an error.
